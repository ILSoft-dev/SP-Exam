<div class="tldr" markdown="1">
**Графическая подсистема Windows** построена по принципу **независимости от устройства**: программа рисует одними и теми же функциями **GDI** (Graphics Device Interface) на экране, принтере, в памяти или метафайле. Различия скрывают **драйверы устройств**.

Слои:
- приложение → `gdi32.dll`/`user32.dll` (API) → **win32k.sys** (режим ядра) → **драйвер дисплея или принтера** → оборудование;
- над GDI — **GDI+** (сглаживание, PNG/JPEG, альфа-канал);
- современные API — **Direct2D/DirectWrite** и **Direct3D (DirectX)** с аппаратным ускорением;
- окна композирует **DWM** (диспетчер окон рабочего стола).

**Контекст устройства (DC, `HDC`)** — структура GDI, которая связывает программу с устройством вывода и хранит **текущие атрибуты рисования**: выбранные перо, кисть, шрифт, растр, палитру, регион отсечения, цвета текста и фона, режим отображения координат. Все функции рисования принимают `HDC`.

Получение DC: **`BeginPaint`/`EndPaint`** (в `WM_PAINT`), **`GetDC`/`ReleaseDC`** (вне `WM_PAINT`), `GetWindowDC` (всё окно), **`CreateDC`** (принтер, экран), **`CreateCompatibleDC`** (в памяти, для двойной буферизации), `CreateEnhMetaFile` (метафайл).
</div>

## Принципы построения графической подсистемы

1. **Независимость от устройства.** Один и тот же код рисования выводит на экран, принтер или в файл. GDI переводит логические координаты и цвета в возможности конкретного устройства.
2. **Многослойность.** Приложение → API GDI → графический механизм ядра (win32k.sys) → драйвер устройства (DDI) → оборудование.
3. **Объектная модель.** Инструменты рисования — **объекты GDI** (перья, кисти, шрифты, растры, регионы, палитры). Объекты создаются, **выбираются** в контекст устройства и удаляются.
4. **Окна не хранят своё изображение** (в классической модели). При перекрытии окна система просит его **перерисоваться** сообщением `WM_PAINT`, поэтому программа должна уметь восстановить изображение по своим данным. С появлением DWM изображение окна хранится в буфере, но `WM_PAINT` по-прежнему нужен.
5. **Отсечение (clipping).** Рисование ограничивается видимой частью окна: регион отсечения в DC.

### Графические API Windows

| API | Год | Особенности |
|---|---|---|
| **GDI** | 1985 | Базовая 2D-графика, текст, растры, печать. В основном программная отрисовка |
| **GDI+** | 2001 | C++-классы, сглаживание, градиенты, альфа-канал, JPEG/PNG. Используется в WinForms |
| **DirectX (Direct3D)** | 1995 | 3D, игры, аппаратное ускорение на GPU |
| **Direct2D / DirectWrite** | 2009 | Ускоренная 2D-графика и качественный текст |
| **WPF, WinUI** | 2006 / 2018 | Декларативные интерфейсы поверх DirectX |
| **DWM** | Vista | Композиция окон: каждое окно рисуется во внеэкранный буфер, затем DWM собирает их на GPU (прозрачность, эскизы) |

## Контекст устройства

**Контекст устройства (DC)** — внутренняя структура GDI, через которую программа рисует. Программа получает дескриптор **`HDC`** и передаёт его во все функции вывода.

### Что хранится в DC (атрибуты)

| Атрибут | По умолчанию | Функция изменения |
|---|---|---|
| Перо | `BLACK_PEN` | `SelectObject` |
| Кисть | `WHITE_BRUSH` | `SelectObject` |
| Шрифт | `SYSTEM_FONT` | `SelectObject` |
| Растр (для DC памяти) | Монохромный 1×1 | `SelectObject` |
| Регион отсечения | Клиентская область | `SelectClipRgn` |
| Цвет текста / фона | Чёрный / белый | `SetTextColor`, `SetBkColor` |
| Режим фона | `OPAQUE` | `SetBkMode(TRANSPARENT)` |
| Режим рисования (ROP2) | `R2_COPYPEN` | `SetROP2` |
| Текущая позиция | (0, 0) | `MoveToEx` |
| Режим отображения | `MM_TEXT` | `SetMapMode` |
| Начало координат, масштаб | (0,0) | `SetViewportOrgEx`, `SetWindowExtEx` |
| Выравнивание текста | Левый верхний угол | `SetTextAlign` |

### Типы контекстов устройства

| Тип | Как получить | Для чего |
|---|---|---|
| **Контекст окна (клиентской области)** | `BeginPaint` / `EndPaint` | Рисование в ответ на `WM_PAINT` |
| | `GetDC` / `ReleaseDC` | Рисование в любой момент (например, при движении мыши) |
| **Контекст всего окна** | `GetWindowDC` | Включая заголовок и рамку |
| **Контекст устройства** | `CreateDC(L"DISPLAY", …)`, `CreateDC` для принтера / `DeleteDC` | Экран целиком, принтер |
| **Информационный** | `CreateIC` | Только получение характеристик устройства без рисования |
| **Контекст памяти** | `CreateCompatibleDC` / `DeleteDC` | Рисование в растр в памяти, двойная буферизация |
| **Метафайл** | `CreateEnhMetaFile` / `CloseEnhMetaFile` | Запись команд GDI в файл `.emf` |

Характеристики устройства: `GetDeviceCaps(hdc, HORZRES)` (ширина в пикселях), `LOGPIXELSX` (DPI), `BITSPIXEL`, `RASTERCAPS`.

### WM_PAINT, BeginPaint и регион обновления

- Когда часть окна становится **недействительной** (окно открыли, развернули, программа вызвала `InvalidateRect`), система накапливает **регион обновления** и посылает `WM_PAINT`.
- **`BeginPaint`** возвращает DC, у которого **отсечение = регион обновления**, заполняет `PAINTSTRUCT` (поле `rcPaint`), стирает фон (`WM_ERASEBKGND`) и **делает регион действительным**. Без этого `WM_PAINT` будет приходить бесконечно.
- `EndPaint` освобождает DC.
- `InvalidateRect(hwnd, NULL, TRUE)` — запросить перерисовку. `UpdateWindow` — перерисовать немедленно. `ValidateRect` — пометить действительным.

```c
case WM_PAINT: {
    PAINTSTRUCT ps;
    HDC hdc = BeginPaint(hwnd, &ps);
    HPEN pen   = CreatePen(PS_SOLID, 3, RGB(200, 0, 0));
    HPEN old   = (HPEN)SelectObject(hdc, pen);    // выбрать перо в DC
    Rectangle(hdc, 20, 20, 200, 120);
    SelectObject(hdc, old);                         // вернуть старое
    DeleteObject(pen);                              // удалить своё
    EndPaint(hwnd, &ps);
    return 0;
}
```

<div class="warn" markdown="1">
**Правила работы с DC:**
- каждому `GetDC` — свой `ReleaseDC`, каждому `CreateDC` — `DeleteDC`, `BeginPaint` — только в `WM_PAINT` и в паре с `EndPaint`;
- перед удалением своего объекта GDI **верните в DC старый объект**: объект, выбранный в DC, удалять нельзя;
- не храните `HDC` от `GetDC` между сообщениями (если только у класса нет стиля `CS_OWNDC`). Иначе будет утечка ресурсов GDI (лимит около 10 000 объектов на процесс).
</div>

## Системы координат и режимы отображения

- **Логические координаты** — в них программа задаёт фигуры. **Физические (устройства)** — пиксели или точки принтера.
- **Режим отображения** (`SetMapMode`) задаёт преобразование:

| Режим | Единица | Ось Y |
|---|---|---|
| `MM_TEXT` (по умолчанию) | 1 пиксель | Вниз |
| `MM_LOMETRIC` / `MM_HIMETRIC` | 0,1 мм / 0,01 мм | Вверх |
| `MM_LOENGLISH` / `MM_HIENGLISH` | 0,01 / 0,001 дюйма | Вверх |
| `MM_TWIPS` | 1/1440 дюйма | Вверх |
| `MM_ISOTROPIC` / `MM_ANISOTROPIC` | Задаётся программой (`SetWindowExtEx`, `SetViewportExtEx`) | Любая |

- Начало координат: `SetViewportOrgEx` (в единицах устройства), `SetWindowOrgEx` (в логических). Преобразование: `LPtoDP`, `DPtoLP`.
- Метрические режимы дают **одинаковые физические размеры** на экране и принтере, это и есть независимость от устройства.
