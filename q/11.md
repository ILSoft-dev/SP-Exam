<div class="tldr" markdown="1">
Управляя виртуальной памятью, ОС решает **четыре задачи**:
1. **Размещение (placement)** — **куда** в физической памяти поместить загружаемую страницу или сегмент. Для страниц — в любой свободный кадр. Для сегментов — стратегии first fit / best fit.
2. **Перемещение (выборка, fetch)** — **когда и что** переносить с диска в ОЗУ: **по требованию** (demand paging, при страничном прерывании) или **с упреждением** (prefetch, подгрузка соседних страниц).
3. **Преобразование адресов** — отображение виртуального адреса в физический при каждом обращении: **MMU**, таблицы страниц и сегментов, **TLB**.
4. **Замещение (replacement)** — **какую** страницу вытеснить на диск, если свободных кадров нет. Алгоритмы: **OPT** (эталон), **FIFO**, **LRU**, **NRU**, **«часы» (вторая попытка)**, **LFU**, **рабочее множество**.

Неудачное управление приводит к **пробуксовке (thrashing)**: процесс постоянно вызывает страничные прерывания и почти не выполняется.
</div>

## 1. Задача размещения

**Куда** поместить данные, загружаемые с диска?

- **Страничная организация:** все кадры одинаковы, поэтому страницу можно поместить **в любой свободный** кадр. Задача тривиальна. ОС ведёт список свободных кадров (в Windows — списки страниц: zeroed, free, standby, modified).
- **Сегментная организация:** нужен **непрерывный участок** достаточного размера → стратегии **first fit, best fit, worst fit, next fit**. Возможна внешняя фрагментация и сжатие ([вопрос 8]({{ '/q/08.html' | relative_url }})).
- В многопроцессорных системах **NUMA** важно размещать страницы в памяти, «близкой» к процессору.

## 2. Задача перемещения (выборки)

**Когда** и **какие** данные загружать с диска в ОЗУ?

- **Выборка по требованию (demand paging):** страница загружается только при **страничном прерывании**, то есть при первом обращении. Нет лишних загрузок, но в начале работы процесса много прерываний.
- **Выборка с упреждением (prefetching, prepaging):** вместе с нужной страницей загружаются **соседние**, на которые скорее всего будет обращение (принцип пространственной локальности). Чтение нескольких последовательных страниц с диска выгоднее, чем по одной.
  - Windows: **кластеризация** страничных прерываний (подгрузка нескольких страниц), **SuperFetch / SysMain** — предварительная загрузка часто используемых программ, **Prefetcher** при старте.
  - Linux: readahead для файлов.
- Также решается, **куда выгружать**: в **файл подкачки** (`pagefile.sys`, swap) или в исходный файл (для кода и проецируемых файлов неизменённые страницы не сохраняются — их можно перечитать из EXE или DLL).

## 3. Задача преобразования адресов

При **каждом** обращении к памяти виртуальный адрес преобразуется в физический:
- выполняет аппаратура — **MMU**;
- данные берутся из **таблиц страниц** (сегментов) процесса, которые формирует ОС;
- **TLB** кеширует последние преобразования;
- при отсутствии страницы (бит P = 0) возникает **страничное прерывание**, и ОС решает задачи 2, 1 и 4.

Подробно о схемах преобразования: [вопрос 9]({{ '/q/09.html' | relative_url }}).

## 4. Задача замещения

Если **свободных кадров нет**, какую страницу вытеснить?

### Алгоритмы замещения

| Алгоритм | Какую страницу вытесняет | Особенности |
|---|---|---|
| **OPT** (оптимальный, Белади) | К которой обратятся **позже всех** | Нереализуем, эталон для сравнения |
| **FIFO** | Загруженную **раньше всех** | Прост. Возможна **аномалия Белади** (больше кадров — больше прерываний) |
| **LRU** | **Дольше всех не использовавшуюся** | Близок к OPT, дорого реализовать точно (нужна метка времени или стек) |
| **NRU** | Из наименьшего класса по битам (R, M): (0,0) → (0,1) → (1,0) → (1,1) | Биты R периодически сбрасываются |
| **«Часы» (вторая попытка)** | Идёт по кругу: R = 1 → сбросить и пропустить, R = 0 → вытеснить | Приближение LRU, широко используется |
| **LFU / NFU** | С наименьшим числом обращений | Помнит старую «популярность» |
| **Старение (aging)** | Со сдвиговым счётчиком минимального значения | Хорошее программное приближение LRU |
| **Рабочее множество / WSClock** | Не входящую в рабочее множество (не использовалась за последние τ) | Учитывает локальность |

### Пример (3 кадра, обращения 1 2 3 4 1 2 5 1 2 3 4 5)

| Алгоритм | Страничных прерываний |
|---|---|
| OPT | **7** |
| FIFO | **9** (с 4 кадрами — 10: аномалия Белади) |
| LRU | **10** |

### Локальное и глобальное замещение

- **Локальное** — жертва выбирается среди страниц **этого же** процесса. Каждый процесс имеет свой **резидентный набор** (в Windows — **рабочий набор** с минимумом и максимумом).
- **Глобальное** — среди страниц всех процессов.
- **Windows:** рабочие наборы процессов, **диспетчер рабочих наборов** при нехватке памяти «подрезает» их. Вытесненные страницы попадают в списки **standby** (без изменений) или **modified** (будут записаны) и могут быть быстро возвращены (**мягкий страничный сбой**).
- **Linux:** списки active/inactive (приближение LRU), демон `kswapd`.

### Пробуксовка (thrashing)

Если процессам выделено меньше кадров, чем нужно для их **рабочих множеств**, они постоянно вызывают страничные прерывания. Процессор простаивает в ожидании диска, а ОС, видя низкую загрузку, запускает ещё процессы, и становится только хуже.

**Решения:** модель рабочего множества (держать в памяти всё рабочее множество или выгрузить процесс целиком), контроль **частоты страничных прерываний** (PFF), уменьшение уровня мультипрограммирования.
