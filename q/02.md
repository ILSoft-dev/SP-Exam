<div class="tldr" markdown="1">
**Процесс** — программа в стадии выполнения вместе с выделенными ей ресурсами: **виртуальным адресным пространством**, открытыми файлами, дескрипторами, правами. Процесс — **единица владения ресурсами**.

**Поток (нить, thread)** — последовательность выполнения команд внутри процесса. У потока есть **свой счётчик команд, регистры и стек**, а память и ресурсы он разделяет с другими потоками процесса. Поток — **единица планирования** процессорного времени.

**Ресурс** — любой объект, который процесс может использовать и который выделяет ОС: процессорное время, память, устройства, файлы, данные.

**Классификация процессов:** последовательные и параллельные; независимые и взаимодействующие; системные и пользовательские; интерактивные (переднего плана) и фоновые; вычислительные и с интенсивным вводом-выводом.

**Классификация ресурсов:** физические и логические (виртуальные); аппаратные и программные; **повторно используемые** (процессор, принтер) и **потребляемые** (сообщения, сигналы); **разделяемые** и **неразделяемые (монопольные)**; **вытесняемые** и **невытесняемые**.
</div>

## Процесс

ОС рассматривает процесс как **заявку на потребление ресурсов**. Программа — это пассивный файл на диске, а процесс — активная сущность: программа, загруженная в память и выполняющаяся.

**Что входит в процесс:**
- **код** и **данные** программы;
- **адресное пространство**: код, данные, куча, стеки;
- **системные ресурсы**: открытые файлы, сокеты, объекты синхронизации;
- **информация для ОС** — дескриптор процесса (PCB): идентификатор, состояние, приоритет, права;
- как минимум **один поток**.

### Свойства процесса

- **Динамичность** — процесс существует во времени: создаётся, выполняется, завершается.
- **Изолированность** — у каждого процесса своё адресное пространство, процессы защищены друг от друга.
- **Асинхронность** — процессы выполняются с непредсказуемыми относительными скоростями.
- **Параллельность (конкурентность)** — несколько процессов могут выполняться одновременно или попеременно.
- **Наличие состояния** — выполнение, готовность, ожидание ([вопрос 4]({{ '/q/04.html' | relative_url }})).

### Классификация процессов

| Признак | Виды |
|---|---|
| По способу выполнения | **Последовательные** (одна нить управления) и **параллельные** (несколько процессов или потоков одновременно) |
| По взаимосвязи | **Независимые** и **взаимодействующие** (обмениваются данными, конкурируют за ресурсы) |
| По принадлежности | **Системные** (службы, демоны) и **пользовательские** |
| По режиму работы | **Интерактивные** (переднего плана) и **фоновые** (службы Windows, демоны UNIX) |
| По характеру нагрузки | **Вычислительные** (CPU-bound) и **с интенсивным вводом-выводом** (I/O-bound) |
| По времени реакции | Обычные и **реального времени** |

## Поток

Потоки позволяют **распараллелить работу внутри одного приложения** без затрат на создание процессов. Например, в браузере один поток отрисовывает страницу, другой загружает данные, третий выполняет скрипт.

| | Процесс | Поток |
|---|---|---|
| Роль | Единица владения ресурсами | Единица планирования |
| Адресное пространство | Своё | Общее с потоками процесса |
| Своё у каждого | Память, открытые файлы, PID | Регистры, счётчик команд, **стек**, TID, TLS |
| Создание и переключение | Дорого | Дёшево |
| Обмен данными | Через IPC | Через общую память, но нужна синхронизация |
| Сбой | Не затрагивает другие процессы | Может уничтожить весь процесс |

**Виды потоков:** потоки **ядра** — их планирует ОС (Windows, Linux); потоки **пользовательского уровня** — реализуются библиотекой, ядро видит только процесс; **волокна (fibers)** в Windows — потоки с кооперативным переключением внутри потока ядра.

## Ресурс

**Ресурс** — любой потребляемый объект, независимо от формы его существования, который нужен процессу для работы.

### Классификация ресурсов

| Признак | Виды и примеры |
|---|---|
| **По природе** | **Аппаратные (физические)**: процессор, память, диски, принтер. **Программные (логические)**: файлы, буферы, семафоры, сообщения |
| **По реальности** | **Физические** (реально существующие) и **виртуальные** (модель физического ресурса: виртуальная память, виртуальный принтер при спулинге) |
| **По возможности повторного использования** | **Повторно используемые** (reusable) не исчезают после использования: процессор, память, устройства. **Потребляемые** (consumable) исчезают после использования: сообщения, сигналы, прерывания |
| **По способу использования** | **Разделяемые** — допускают одновременное или попеременное использование несколькими процессами (диск, файл для чтения). **Неразделяемые (монопольные, критические)** — в каждый момент используются только одним процессом (принтер, переменная при записи) |
| **По возможности отбора** | **Вытесняемые (preemptible)** — ресурс можно отобрать и вернуть позже без ущерба: процессор, память (выгрузка на диск). **Невытесняемые** — отбор ведёт к ошибке: принтер посреди печати, запись в файл |
| **По количеству** | Единичные и множественные (несколько однотипных экземпляров) |
| **По активности** | **Активные** — способны изменять информацию: процессор. **Пассивные** — хранят информацию: память, файлы |

<div class="tip" markdown="1">
Классификация ресурсов важна для [тупиков]({{ '/q/06.html' | relative_url }}): тупик возможен только для **неразделяемых** и **невытесняемых** ресурсов. Вытесняемый ресурс можно просто отобрать.
</div>

## Дескриптор и контекст

- **Дескриптор процесса (PCB)** — информация, которая нужна ОС **всегда**: идентификатор, состояние, приоритет, адрес таблицы страниц, список ресурсов.
- **Контекст** — информация, нужная **для возобновления** выполнения: регистры, счётчик команд, указатель стека, флаги.
