<div class="tldr" markdown="1">
**Очереди сообщений:**
- **системная очередь аппаратного ввода** — одна на систему (точнее, на рабочий стол);
- **очередь сообщений потока** — у каждого GUI-потока своя.

Поток необработанного ввода (**RIT**) переносит события клавиатуры и мыши из системной очереди в очередь потока, которому принадлежит нужное окно. `GetMessage` выбирает сообщения в порядке приоритета: отправленные `SendMessage` → поставленные `PostMessage` → ввод → `WM_PAINT` → `WM_TIMER`.

**Клавиатура:** сообщения получает окно с **фокусом ввода** (`SetFocus`, `WM_SETFOCUS`/`WM_KILLFOCUS`).
- `WM_KEYDOWN` / `WM_KEYUP` — нажатие и отпускание; `wParam` содержит **виртуальный код клавиши** (`VK_LEFT`, `VK_RETURN`, `'A'`);
- `WM_CHAR` — **символ** с учётом раскладки и регистра, его создаёт `TranslateMessage`;
- `WM_SYSKEYDOWN` — с Alt.
- Состояние клавиш: `GetKeyState`, `GetAsyncKeyState`.

**Мышь:** окно под курсором (или окно, **захватившее мышь** через `SetCapture`) получает:
- `WM_MOUSEMOVE`, `WM_LBUTTONDOWN`/`UP`, `WM_RBUTTONDOWN`, `WM_LBUTTONDBLCLK` (нужен стиль класса `CS_DBLCLKS`), `WM_MOUSEWHEEL`;
- в `lParam` — координаты **в клиентской области**, в `wParam` — состояние кнопок и Shift/Ctrl (`MK_LBUTTON`, `MK_SHIFT`, `MK_CONTROL`);
- **неклиентские** сообщения `WM_NC…` относятся к рамке и заголовку.

## Очереди сообщений

<pre class="diagram">
Клавиатура/мышь → драйвер → Системная очередь ввода
                                    │
                         RIT (win32k.sys): какому
                         окну? (фокус / под курсором)
                    ┌───────────────┼──────────────┐
                    ▼               ▼              ▼
             Очередь потока A  Очередь потока B  ...
                    │
             GetMessage/PeekMessage
                    │
             DispatchMessage → WndProc окна
</pre>

- Очередь сообщений создаётся у потока при первом вызове функции USER или GDI.
- Каждое окно принадлежит **потоку, который его создал**, и его сообщения попадают в очередь этого потока.
- Если поток долго не выбирает сообщения (дольше примерно 5 секунд), Windows считает окно **«не отвечающим»** и показывает «призрачное» окно.

### Порядок выборки в GetMessage

1. Сообщения, отправленные **`SendMessage`** из других потоков. Они обрабатываются сразу внутри `GetMessage`.
2. Сообщения, поставленные **`PostMessage`** (отправленные в очередь).
3. **Аппаратный ввод** (клавиатура, мышь).
4. Снова сообщения `SendMessage`.
5. **`WM_PAINT`** — только если других сообщений нет. Это не настоящее сообщение в очереди, а флаг «есть недействительная область».
6. **`WM_TIMER`** — тоже генерируется, когда очередь пуста.

Поэтому `WM_PAINT` и `WM_TIMER` имеют низший приоритет и **объединяются**: несколько запросов перерисовки дают одно сообщение.

### Синхронные и асинхронные сообщения

| | `SendMessage` | `PostMessage` |
|---|---|---|
| Очередь | Нет, прямой вызов оконной процедуры | Да, ставится в очередь потока окна |
| Ожидание | Ждёт завершения обработки и получает результат | Возвращается сразу |
| Окно в другом потоке | Вызывающий поток блокируется, пока целевой поток не обработает | Без блокировки |
| Риски | Взаимоблокировка, если целевой поток завис (есть `SendMessageTimeout`) | Нельзя передавать указатели на локальные данные |

Другие функции: `PostThreadMessage` (в очередь потока без окна), `SendNotifyMessage`, `SendMessageCallback`, `WaitMessage`, `MsgWaitForMultipleObjects` (ожидание и сообщений, и объектов ядра).

## Клавиатура

### Фокус ввода

- Клавиатурные сообщения получает **одно окно — с фокусом ввода**. Это активное окно или его дочернее окно.
- `SetFocus(hwnd)`, `GetFocus()`. При смене окно получает `WM_SETFOCUS` / `WM_KILLFOCUS`. В ответ на них обычно создают и уничтожают **каретку** (`CreateCaret`, `ShowCaret`, `DestroyCaret`).

### Сообщения клавиатуры

| Сообщение | Когда | wParam |
|---|---|---|
| `WM_KEYDOWN` | Нажатие клавиши (повторяется при удержании) | Виртуальный код `VK_*` |
| `WM_KEYUP` | Отпускание | Виртуальный код |
| `WM_SYSKEYDOWN` / `WM_SYSKEYUP` | Клавиша с **Alt** или F10 (системные) | Виртуальный код |
| `WM_CHAR` | Символ (после `TranslateMessage`) | Код символа (UTF-16) |
| `WM_DEADCHAR` | «Мёртвая» клавиша (диакритика) | |

**`lParam`** клавиатурных сообщений: счётчик повторов (биты 0–15), **скан-код** (16–23), флаг расширенной клавиши (24), Alt (29), предыдущее состояние (30), переход (31).

**Виртуальные коды:** `VK_RETURN`, `VK_ESCAPE`, `VK_SPACE`, `VK_LEFT`/`VK_RIGHT`/`VK_UP`/`VK_DOWN`, `VK_F1`…`VK_F24`, `VK_SHIFT`, `VK_CONTROL`, `VK_MENU` (Alt), `VK_DELETE`. Буквы и цифры — коды `'A'`…`'Z'`, `'0'`…`'9'`.

**Скан-код** зависит от клавиатуры, **виртуальный код** — от неё не зависит, а **символ** зависит от раскладки и Shift.

```c
case WM_KEYDOWN:
    switch (wParam) {
    case VK_LEFT:  x -= 10; InvalidateRect(hwnd, NULL, TRUE); break;
    case VK_RIGHT: x += 10; InvalidateRect(hwnd, NULL, TRUE); break;
    case VK_ESCAPE: DestroyWindow(hwnd); break;
    }
    if (wParam == 'S' && (GetKeyState(VK_CONTROL) & 0x8000))  // Ctrl+S
        SaveDocument();
    return 0;

case WM_CHAR:                      // ввод текста
    if (wParam == '\b') { /* Backspace */ }
    else text[len++] = (WCHAR)wParam;
    InvalidateRect(hwnd, NULL, TRUE);
    return 0;
```

- **`GetKeyState(vk)`** — состояние клавиши на момент **текущего сообщения** (старший бит — нажата, младший — переключатель Caps Lock).
- **`GetAsyncKeyState(vk)`** — физическое состояние **прямо сейчас**.
- **Ускорители (горячие клавиши):** таблица `ACCELERATORS` в ресурсах, `LoadAccelerators` и `TranslateAccelerator` в цикле сообщений. Результат — `WM_COMMAND`.

## Мышь

### Сообщения клиентской области

| Сообщение | Событие |
|---|---|
| `WM_MOUSEMOVE` | Перемещение |
| `WM_LBUTTONDOWN` / `UP` / `DBLCLK` | Левая кнопка |
| `WM_RBUTTONDOWN` / `UP` / `DBLCLK` | Правая |
| `WM_MBUTTONDOWN` … | Средняя |
| `WM_MOUSEWHEEL` | Колесо (`GET_WHEEL_DELTA_WPARAM(wParam)`, кратно 120) |
| `WM_MOUSEHOVER` / `WM_MOUSELEAVE` | Задержка и уход курсора (нужен `TrackMouseEvent`) |

- **`lParam`** содержит координаты относительно **левого верхнего угла клиентской области**: `GET_X_LPARAM(lParam)`, `GET_Y_LPARAM(lParam)` из `<windowsx.h>`. Для колеса координаты экранные.
- **`wParam`** — флаги: `MK_LBUTTON`, `MK_RBUTTON`, `MK_MBUTTON`, `MK_SHIFT`, `MK_CONTROL`.
- **Двойной щелчок** приходит, только если у класса окна стиль `CS_DBLCLKS`. Последовательность: DOWN, UP, **DBLCLK**, UP.

```c
case WM_LBUTTONDOWN:
    drawing = TRUE;
    last.x = GET_X_LPARAM(lParam); last.y = GET_Y_LPARAM(lParam);
    SetCapture(hwnd);                  // получать мышь и за пределами окна
    return 0;
case WM_MOUSEMOVE:
    if (drawing && (wParam & MK_LBUTTON)) {
        HDC hdc = GetDC(hwnd);
        MoveToEx(hdc, last.x, last.y, NULL);
        last.x = GET_X_LPARAM(lParam); last.y = GET_Y_LPARAM(lParam);
        LineTo(hdc, last.x, last.y);   // рисование «карандашом»
        ReleaseDC(hwnd, hdc);
    }
    return 0;
case WM_LBUTTONUP:
    drawing = FALSE;
    ReleaseCapture();
    return 0;
```

### Неклиентские сообщения и проверка попадания

- `WM_NCHITTEST` — система спрашивает, **в какую часть окна** попал курсор: `HTCLIENT`, `HTCAPTION` (заголовок), `HTCLOSE`, `HTLEFT` (рамка) и т. д. `DefWindowProc` отвечает сам. Возвращая `HTCAPTION`, можно перетаскивать окно за клиентскую область.
- `WM_NCLBUTTONDOWN`, `WM_NCMOUSEMOVE` — события в неклиентской области (рамка, заголовок).

### Захват мыши и курсор

- **`SetCapture`** — все сообщения мыши идут этому окну, даже если курсор за его пределами. Нужно для перетаскивания и рисования. `ReleaseCapture` отпускает.
- **Курсор:** `SetCursor` (в ответ на `WM_SETCURSOR`), `LoadCursor`, `ShowCursor`, `GetCursorPos`, `ClipCursor`.
- Пересчёт координат: `ClientToScreen`, `ScreenToClient`.
