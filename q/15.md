<div class="tldr" markdown="1">
**Реальный режим (real mode)** — режим процессора 8086 и режим, в котором стартует любой x86. Физический адрес = **сегмент × 16 + смещение** (20 бит), доступно **1 МБ**. Сегменты по **64 КБ**, **нет защиты памяти** и привилегий: любая программа может всё. Так работала MS-DOS.

**Защищённый режим (protected mode, начиная с 80286/80386):** в сегментный регистр загружается не адрес, а **селектор** — индекс дескриптора в **дескрипторной таблице**:
- **GDT** (глобальная, общая для системы);
- **LDT** (локальная, для задачи);
- **IDT** (таблица дескрипторов прерываний).

**Дескриптор сегмента** (8 байт) содержит **базу** (32 бита), **предел** (20 бит + бит гранулярности G), **права доступа**: тип сегмента (код или данные), **DPL** (уровень привилегий 0–3), бит присутствия **P** и другие.

Физический адрес: селектор → дескриптор → **линейный адрес = база + смещение** (с проверкой предела и прав) → **страничное преобразование** → физический. 4 **кольца защиты**: ring 0 — ядро, ring 3 — приложения. Windows и Linux используют **плоскую модель** (база 0, предел 4 ГБ) и защищают память на уровне страниц.
</div>

## Реальный режим

<pre class="diagram">
Сегментный регистр (16 бит)   ×16
  1234h  →  12340h
+ смещение (16 бит)            0056h
= физический адрес (20 бит)    12396h
</pre>

- Сегментные регистры: **CS** (код), **DS** (данные), **SS** (стек), **ES** (+ FS, GS у 386).
- Адресное пространство **1 МБ** (2²⁰). Сегмент до **64 КБ**.
- Один и тот же физический адрес можно получить разными парами «сегмент:смещение» (1234:0056 = 1239:0006).
- **Нет защиты:** программа может обратиться к любой памяти, в том числе к коду ОС и таблице векторов прерываний (адрес 0000:0000, 256 векторов по 4 байта).
- **Нет привилегий и виртуальной памяти**, только одна задача.
- **Линия A20:** «заворот» адресов за 1 МБ (FFFF:0010 = 0), для совместимости управлялась отдельно.
- Применение: MS-DOS, загрузчики BIOS, начальная стадия загрузки любой x86-ОС.

## Защищённый режим

Появился в **80286** (16 бит, 16 МБ) и развит в **80386** (32 бита, 4 ГБ, страничная организация). Переход: загрузить GDT (`LGDT`), установить бит **PE** в регистре **CR0**, выполнить дальний переход.

### Селектор

<pre class="diagram">
 15                  3  2   1 0
┌─────────────────────┬────┬────┐
│  Индекс дескриптора │ TI │RPL │
└─────────────────────┴────┴────┘
 TI: 0 — GDT, 1 — LDT
 RPL — запрашиваемый уровень привилегий
</pre>

Индекс × 8 — смещение дескриптора в таблице (до 8192 дескрипторов).

### Дескрипторные таблицы

| Таблица | Регистр | Назначение |
|---|---|---|
| **GDT** (Global Descriptor Table) | **GDTR** (база и предел) | Дескрипторы, общие для всех задач: сегменты ядра, TSS, дескрипторы LDT |
| **LDT** (Local Descriptor Table) | **LDTR** (селектор в GDT) | Сегменты конкретной задачи (процесса) |
| **IDT** (Interrupt Descriptor Table) | **IDTR** | Шлюзы прерываний, ловушек и задач для 256 векторов прерываний |

Также есть **TSS** (Task State Segment) — сегмент состояния задачи, в нём хранятся указатели стеков для разных уровней привилегий (в x86-64 — для переключения стека при прерываниях).

### Дескриптор сегмента (8 байт)

| Поле | Размер | Назначение |
|---|---|---|
| **База (Base)** | 32 бита (разбита на части) | Начальный линейный адрес сегмента |
| **Предел (Limit)** | 20 бит | Размер сегмента − 1 |
| **G** (гранулярность) | 1 бит | Предел в байтах (до 1 МБ) или в 4 КБ страницах (до 4 ГБ) |
| **P** (Present) | 1 бит | Сегмент присутствует в памяти. 0 — исключение «сегмент отсутствует» (для подкачки сегментов) |
| **DPL** | 2 бита | Уровень привилегий дескриптора (0–3) |
| **S** | 1 бит | Системный сегмент (0) или сегмент кода/данных (1) |
| **Type** | 4 бита | Код (выполнение, чтение, подчинённый) или данные (запись, расширение вниз), бит обращения A |
| **D/B** | 1 бит | 16- или 32-битный сегмент |
| **L** | 1 бит | 64-битный сегмент кода (x86-64) |
| **AVL** | 1 бит | Доступен ОС |

### Преобразование адреса в защищённом режиме

<pre class="diagram">
 Логический адрес: селектор : смещение
          │
          ▼  GDT/LDT[индекс] → дескриптор
   проверки: P=1? смещение ≤ предел?
             права? CPL/RPL ≤ DPL?
          │
          ▼
 Линейный адрес = база + смещение
          │  (если CR0.PG = 1)
          ▼  каталог страниц → таблица → кадр
 Физический адрес
</pre>

Дескрипторы кешируются в **теневых (скрытых) частях** сегментных регистров, поэтому таблица читается только при загрузке селектора.

### Защита

- **Кольца привилегий:** 0 — ядро ОС, 1–2 — драйверы (практически не используются), 3 — приложения.
- **CPL** — текущий уровень (младшие биты CS), **RPL** — в селекторе, **DPL** — в дескрипторе. Доступ к данным разрешён, если max(CPL, RPL) ≤ DPL.
- Переход на более привилегированный код — только через **шлюзы** (call gate, шлюзы прерываний в IDT) или команды `SYSCALL`/`SYSENTER`.
- Привилегированные команды (`LGDT`, `MOV CR0`, `HLT`, `CLI`, `IN`/`OUT` при IOPL < CPL) в кольце 3 вызывают **исключение общей защиты (#GP)**.
- **Исключения:** #GP (13) — нарушение защиты, #NP (11) — сегмент отсутствует, #SS (12) — ошибка стека, #PF (14) — страничный сбой.

### Страничное преобразование

При **CR0.PG = 1** линейный адрес преобразуется через **каталог страниц** (адрес в **CR3**) и **таблицы страниц**. Права задаются битами **U/S** (пользователь/супервизор), **R/W**, **NX**. Подробно: [вопрос 9]({{ '/q/09.html' | relative_url }}).

## Плоская модель и x86-64

- **Windows и Linux** используют **плоскую модель памяти**: все сегменты кода и данных имеют **базу 0 и предел 4 ГБ**, различаются только DPL (0 для ядра, 3 для пользователя). Сегментация фактически не используется, вся защита и виртуальная память строятся на **страницах**.
- Регистры **FS/GS** указывают на структуры потока: в Windows **TEB** (FS в x86, GS в x64) и **KPCR** в ядре. В Linux — TLS.
- **Режим x86-64 (long mode):** сегментация почти отключена — база и предел игнорируются для CS, DS, ES, SS. Обязательна **4- или 5-уровневая** страничная организация. Адреса 48 или 57 бит в канонической форме.
- **Режим виртуального 8086 (V86)** — выполнение программ реального режима внутри защищённого (NTVDM в 32-битной Windows).

## Сравнение режимов

| | Реальный | Защищённый (32 бита) | Long mode (64 бита) |
|---|---|---|---|
| Адресуемая память | 1 МБ | 4 ГБ (64 ГБ с PAE) | 256 ТБ (48 бит) |
| Формирование адреса | Сегмент × 16 + смещение | Дескриптор + страницы | Почти только страницы |
| Размер сегмента | 64 КБ | До 4 ГБ | Плоское пространство |
| Защита | Нет | Кольца, пределы, права, страницы | Кольца, страницы, NX |
| Многозадачность | Нет | Аппаратная поддержка (TSS) | Программное переключение |
| Пример ОС | MS-DOS | Windows 2000/XP (x86), Linux i386 | Windows 10/11 x64, Linux x86-64 |
