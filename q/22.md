<div class="tldr" markdown="1">
**Сигнал** — асинхронное уведомление процесса о событии (**программное прерывание**). У каждого сигнала есть номер и имя: `SIGINT` (2, Ctrl+C), `SIGKILL` (9), `SIGSEGV` (11), `SIGTERM` (15), `SIGCHLD`, `SIGALRM`, `SIGPIPE`, `SIGUSR1`/`SIGUSR2`, `SIGSTOP`/`SIGCONT`.

**Источники:** ядро (ошибки, таймер, завершение потомка), другой процесс (**`kill`**), терминал (Ctrl+C, Ctrl+Z), сам процесс (`raise`, `abort`, `alarm`).

**Реакции:** действие **по умолчанию** (завершение, дамп памяти, остановка, игнорирование), **игнорирование** (`SIG_IGN`), **свой обработчик** (`signal`, лучше **`sigaction`**). `SIGKILL` и `SIGSTOP` перехватить нельзя. Сигналы можно **блокировать** маской (`sigprocmask`).

**Неименованный канал (`pipe`)** — однонаправленный буфер в ядре, два дескриптора `fd[0]` (чтение) и `fd[1]` (запись). Связывает только **родственные** процессы (через `fork`). Пример — конвейер `ls | wc`.

**Именованный канал (FIFO)** — специальный файл в ФС (`mkfifo`), через него обмениваются **любые** процессы.

**Другие средства IPC:** очереди сообщений, семафоры, разделяемая память (System V и POSIX, [вопрос 23]({{ '/q/23.html' | relative_url }})), **сокеты**, отображаемые файлы `mmap`, файлы с блокировками.
</div>

## Сигналы

### Основные сигналы

| Сигнал | № | Когда | По умолчанию |
|---|---|---|---|
| `SIGHUP` | 1 | Обрыв терминала; демонам — «перечитать конфигурацию» | Завершение |
| `SIGINT` | 2 | **Ctrl+C** | Завершение |
| `SIGQUIT` | 3 | Ctrl+\ | Завершение + дамп (core) |
| `SIGILL` | 4 | Недопустимая команда | Дамп |
| `SIGABRT` | 6 | `abort()` | Дамп |
| `SIGFPE` | 8 | Деление на 0, арифметическая ошибка | Дамп |
| **`SIGKILL`** | 9 | Безусловное уничтожение | Завершение, **нельзя перехватить** |
| `SIGSEGV` | 11 | Нарушение доступа к памяти | Дамп |
| `SIGPIPE` | 13 | Запись в канал без читателей | Завершение |
| `SIGALRM` | 14 | Таймер `alarm()` | Завершение |
| `SIGTERM` | 15 | «Вежливая» просьба завершиться (`kill` по умолчанию) | Завершение |
| `SIGUSR1`, `SIGUSR2` | 10, 12 | Пользовательские | Завершение |
| `SIGCHLD` | 17 | Потомок завершился или остановился | Игнорирование |
| `SIGCONT` | 18 | Продолжить остановленный процесс | Продолжение |
| **`SIGSTOP`** | 19 | Остановка, **нельзя перехватить** | Остановка |
| `SIGTSTP` | 20 | **Ctrl+Z** | Остановка |

(Номера даны для Linux x86. Список: `kill -l`.)

### Отправка сигналов

```c
kill(pid, SIGTERM);   // процессу; pid = 0 — своей группе, −1 — всем доступным
raise(SIGUSR1);       // себе
alarm(5);             // SIGALRM через 5 секунд
abort();              // SIGABRT
```
Команды: `kill -TERM 1234`, `kill -9 1234`, `killall`, `pkill`. Право отправить сигнал есть у владельца процесса (по UID) и у root.

### Обработка сигналов

```c
#include <signal.h>
#include <stdio.h>
#include <unistd.h>

volatile sig_atomic_t got = 0;

void handler(int sig) {          // в обработчике — только безопасные функции
    got = sig;
}

int main(void) {
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);     // какие сигналы блокировать во время обработки
    sa.sa_flags = SA_RESTART;     // перезапускать прерванные системные вызовы
    sigaction(SIGINT, &sa, NULL);
    signal(SIGQUIT, SIG_IGN);     // игнорировать Ctrl+\ (старый интерфейс)

    while (!got) pause();         // ждать сигнал
    printf("получен сигнал %d, завершаюсь корректно\n", got);
    return 0;
}
```

- **`signal()`** — простой, но с непереносимой семантикой (в старых System V обработчик сбрасывался после срабатывания).
- **`sigaction()`** — надёжный POSIX-интерфейс: маска, флаги (`SA_RESTART`, `SA_SIGINFO`), дополнительная информация об источнике.
- **Обработчик** выполняется асинхронно, «посреди» программы. В нём можно вызывать только **async-signal-safe** функции (`write`, `_exit`). Нельзя `printf` и `malloc`. Лучший стиль — установить флаг типа `volatile sig_atomic_t`.
- **Прерванные системные вызовы** возвращают −1 с `errno = EINTR`, если не задан `SA_RESTART`.

### Блокирование (маскирование)

```c
sigset_t set;
sigemptyset(&set);
sigaddset(&set, SIGINT);
sigprocmask(SIG_BLOCK, &set, NULL);    // SIGINT будет отложен
/* критический участок */
sigprocmask(SIG_UNBLOCK, &set, NULL);  // доставлен здесь, если приходил
```

Заблокированный сигнал остаётся **ожидающим (pending)**: `sigpending()`. Обычные сигналы **не накапливаются** — несколько одинаковых превращаются в один. Сигналы **реального времени** (`SIGRTMIN`…`SIGRTMAX`) ставятся в очередь и могут нести данные (`sigqueue`).

Ожидание: `pause()`, `sigsuspend()` (атомарно меняет маску и ждёт), `sigwait()`.

## Неименованные каналы (pipe)

- Создаются вызовом **`pipe(int fd[2])`**: `fd[0]` — для **чтения**, `fd[1]` — для **записи**.
- **Однонаправленные**, **FIFO**, ёмкость буфера ограничена (в Linux по умолчанию 64 КБ).
- Доступны только процессам, которые получили дескрипторы по наследству (**родственным**).
- `read` из пустого канала блокируется. Если все писатели закрыли свой конец, `read` возвращает **0** (конец файла). `write` в канал без читателей приводит к **`SIGPIPE`** / `EPIPE`. Запись до `PIPE_BUF` (4096) байт **атомарна**.

```c
int fd[2];
pipe(fd);
if (fork() == 0) {              // потомок — читатель
    close(fd[1]);
    char buf[100];
    ssize_t n = read(fd[0], buf, sizeof buf);
    printf("потомок получил: %.*s\n", (int)n, buf);
    _exit(0);
}
close(fd[0]);                   // родитель — писатель
write(fd[1], "привет", strlen("привет"));
close(fd[1]);
wait(NULL);
```

**Конвейер `ls -l | wc -l`:**

```c
int fd[2]; pipe(fd);
if (fork() == 0) {               // ls: stdout → канал
    dup2(fd[1], 1); close(fd[0]); close(fd[1]);
    execlp("ls", "ls", "-l", NULL); _exit(127);
}
if (fork() == 0) {               // wc: stdin ← канал
    dup2(fd[0], 0); close(fd[0]); close(fd[1]);
    execlp("wc", "wc", "-l", NULL); _exit(127);
}
close(fd[0]); close(fd[1]);      // иначе wc не увидит конец данных
wait(NULL); wait(NULL);
```

Упрощённо: `FILE *p = popen("ls -l", "r"); … pclose(p);`

## Именованные каналы (FIFO)

- Специальный файл типа `p` в файловой системе: `mkfifo("/tmp/myfifo", 0666)` или команда `mkfifo`.
- Открывается обычным `open`. Доступен **любым** процессам с правами на файл.
- `open` на чтение **блокируется**, пока кто-то не откроет на запись, и наоборот (если не `O_NONBLOCK`).
- Данные не записываются на диск: файл — только «точка встречи».

```c
/* сервер */                              /* клиент */
mkfifo("/tmp/fifo", 0666);                int fd = open("/tmp/fifo", O_WRONLY);
int fd = open("/tmp/fifo", O_RDONLY);     write(fd, "hello", 5);
char b[64]; int n = read(fd, b, 64);      close(fd);
```

## Дополнительные средства IPC

| Средство | Особенности |
|---|---|
| **Очереди сообщений** (System V `msgget`, POSIX `mq_open`) | Сообщения с типом и приоритетом, сохраняются границы |
| **Семафоры** (`semget`, `sem_open`) | Синхронизация процессов |
| **Разделяемая память** (`shmget`, `shm_open` + `mmap`) | Самый быстрый обмен, нужна синхронизация |
| **Отображение файлов** `mmap` | Общий файл в памяти нескольких процессов |
| **Сокеты** (`AF_UNIX`, `AF_INET`) | Двунаправленные, локально и по сети. `socketpair()` — пара связанных сокетов |
| **Файлы с блокировками** | `fcntl(F_SETLK)`, `flock` |
| **Сигналы реального времени** с данными | `sigqueue` |
| **D-Bus**, **eventfd**, **signalfd** | Современные механизмы Linux |
