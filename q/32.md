<div class="tldr" markdown="1">
**DLL (Dynamic Link Library)** — динамически подключаемая библиотека: модуль с кодом и данными (функциями, ресурсами, классами), который **подключается к процессу во время загрузки или выполнения**, а не вшивается в EXE при компоновке.

**Статическая компоновка** (`.lib`) включает код библиотеки **в каждый EXE**. **Динамическая** оставляет в EXE только ссылки, а код DLL загружается в память **один раз** и **разделяется** процессами.

**Структура DLL:** формат PE, как у EXE, но с флагом «библиотека» и **таблицей экспорта**. Функции помечаются `__declspec(dllexport)` или перечисляются в `.def`-файле. При сборке DLL создаётся **DLL** и **библиотека импорта** (`.lib`).

**Два способа использования:**
- **неявное (загрузочное) связывание** — через `.lib`-заглушку и заголовок, DLL загружается при старте EXE;
- **явное (динамическое)** — `LoadLibrary` → `GetProcAddress` → вызов → `FreeLibrary`, в нужный момент.

**`DllMain`** — необязательная функция инициализации, вызывается при подключении и отключении DLL и потоков.

➕ Экономия памяти и диска, обновление без перекомпиляции EXE, модульность, плагины, локализация. ➖ Проблема совместимости версий («DLL hell»).
</div>

## Статическая и динамическая компоновка

| | Статическая библиотека (`.lib`) | Динамическая библиотека (`.dll`) |
|---|---|---|
| Когда подключается код | При **компоновке** в EXE | При **загрузке** или **выполнении** |
| Размер EXE | Больше (код внутри) | Меньше (только ссылки) |
| Память | Своя копия кода в каждом процессе | **Одна копия** кода разделяется процессами |
| Обновление | Нужна перекомпоновка EXE | Заменить файл DLL |
| Зависимости | Нет внешних файлов | Нужны файлы DLL при запуске |

## Структура DLL

- Формат **PE (Portable Executable)**, как у EXE, но в заголовке установлен флаг `IMAGE_FILE_DLL`.
- Есть **таблица экспорта** (`.edata`) — какие функции и переменные DLL предоставляет наружу (по имени или по порядковому номеру — ordinal).
- У использующего модуля есть **таблица импорта** (`.idata`) — какие функции из каких DLL ему нужны. При загрузке Windows заполняет **IAT** (Import Address Table) реальными адресами.
- Точка входа — **`DllMain`** (необязательно).

## Создание DLL

**Экспорт функций** — два способа:

```c
// mathlib.h
#ifdef MATHLIB_EXPORTS
  #define MATHLIB_API __declspec(dllexport)   // при сборке DLL
#else
  #define MATHLIB_API __declspec(dllimport)   // при использовании
#endif

#ifdef __cplusplus
extern "C" {                 // отключить декорирование имён C++
#endif
MATHLIB_API int  Add(int a, int b);
MATHLIB_API int  Mul(int a, int b);
#ifdef __cplusplus
}
#endif
```

```c
// mathlib.c
#define MATHLIB_EXPORTS
#include "mathlib.h"
MATHLIB_API int Add(int a, int b) { return a + b; }
MATHLIB_API int Mul(int a, int b) { return a * b; }
```

Либо через **файл определений `.def`**:
```text
LIBRARY mathlib
EXPORTS
    Add   @1
    Mul   @2
```

**Сборка** (MSVC): `cl /LD mathlib.c` → создаются `mathlib.dll` и библиотека импорта `mathlib.lib`. (MinGW: `gcc -shared -o mathlib.dll mathlib.c -Wl,--out-implib,libmathlib.a`.)

### DllMain

```c
#include <windows.h>

BOOL WINAPI DllMain(HINSTANCE hinst, DWORD reason, LPVOID reserved) {
    switch (reason) {
    case DLL_PROCESS_ATTACH:  /* DLL загружена в процесс (инициализация) */ break;
    case DLL_THREAD_ATTACH:   /* в процессе создан новый поток */           break;
    case DLL_THREAD_DETACH:   /* поток завершился */                        break;
    case DLL_PROCESS_DETACH:  /* DLL выгружается (очистка) */               break;
    }
    return TRUE;   // FALSE при PROCESS_ATTACH → загрузка не удалась
}
```

<div class="warn" markdown="1">
В `DllMain` действует **«блокировка загрузчика» (loader lock)**: нельзя вызывать `LoadLibrary`, создавать потоки с ожиданием, использовать другие DLL. Сложную инициализацию выносят в отдельную экспортируемую функцию.
</div>

## Использование DLL

### Неявное (загрузочное, implicit) связывание

Программа подключает **заголовок** и **библиотеку импорта** `.lib`. DLL загружается автоматически при старте EXE.

```c
#include "mathlib.h"
#pragma comment(lib, "mathlib.lib")   // или добавить .lib в проект

int main(void) {
    printf("%d\n", Add(2, 3));   // вызов как обычной функции
}
```
- ➕ Просто, вызовы выглядят как обычные.
- ➖ Если DLL нет при запуске — программа **не стартует** с ошибкой.

### Явное (динамическое, explicit) связывание

DLL загружается **в нужный момент** вызовами:

```c
typedef int (*AddFn)(int, int);

HMODULE lib = LoadLibraryW(L"mathlib.dll");
if (lib) {
    AddFn add = (AddFn)GetProcAddress(lib, "Add");   // поиск функции по имени
    if (add) printf("%d\n", add(2, 3));
    FreeLibrary(lib);                                 // выгрузить
}
```
- ➕ Программа работает, даже если DLL нет (можно обработать отсутствие). Подходит для **плагинов** и загрузки по требованию.
- ➖ Больше кода, нужны указатели на функции.

## Что можно экспортировать

- **функции** (чаще всего);
- **переменные** (`__declspec(dllexport) int x;`);
- **классы C++** (`class __declspec(dllexport) …`) — но тогда компилятор обеих сторон должен совпадать;
- **ресурсы** (значки, строки, диалоги) — DLL часто используют как контейнеры ресурсов и для локализации.

**Декорирование имён:** компилятор C++ «украшает» имена (name mangling). Чтобы функцию можно было найти по простому имени из `GetProcAddress` и вызывать из других языков, её объявляют `extern "C"`.

## Данные DLL и разделяемая память

- По умолчанию **данные DLL у каждого процесса свои** (копируются при записи), хотя код общий.
- Чтобы сделать **общую для всех процессов** область, создают именованную секцию:
  ```c
  #pragma data_seg(".shared")
  int g_shared = 0;
  #pragma data_seg()
  #pragma comment(linker, "/SECTION:.shared,RWS")
  ```
  (надёжнее — проецируемые файлы `CreateFileMapping`).

## Проблема версий и способы её решения

**«DLL hell»** — конфликт версий: новая программа заменила общую DLL, и старые перестали работать.
Решения: **SxS (Side-by-Side)** и манифесты, **приватные DLL** рядом с EXE, папка WinSxS, строгие версии (сборки .NET), статическая компоновка критичных библиотек.

## Применение DLL

- **Системные библиотеки Windows:** `kernel32.dll`, `user32.dll`, `gdi32.dll`, `ntdll.dll`, `advapi32.dll`.
- **Библиотеки времени выполнения** (CRT, `msvcrt.dll`, `vcruntime`).
- **Плагины и расширения** (кодеки, фильтры, драйверы печати).
- **Локализация** (ресурсные DLL).
- **COM-серверы** (`.dll` с `DllGetClassObject`).
- **Экономия памяти:** одна копия кода популярной библиотеки для всех процессов.

Инструменты: `dumpbin /exports mathlib.dll`, `dumpbin /imports app.exe`, Dependency Walker, Dependencies.
