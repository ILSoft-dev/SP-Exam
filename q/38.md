<div class="tldr" markdown="1">
**Драйвер** — компонент режима ядра, который управляет устройством или предоставляет службу ядра, по единому интерфейсу диспетчера ввода-вывода.

**Структура драйвера** — набор процедур (точек входа):
- **`DriverEntry`** — главная точка входа, вызывается при загрузке; заполняет **объект драйвера**: регистрирует диспетчерские функции, Unload, AddDevice;
- **`AddDevice`** (в PnP-драйверах) — создаёт **объект устройства** для каждого обнаруженного устройства;
- **диспетчерские процедуры** (`MajorFunction[IRP_MJ_CREATE]`, `IRP_MJ_READ`, `IRP_MJ_WRITE`, `IRP_MJ_DEVICE_CONTROL`, `IRP_MJ_CLOSE`…) — обрабатывают запросы;
- **ISR** и **DPC** — обработка прерываний ([вопрос 35]({{ '/q/35.html' | relative_url }}));
- **Unload** — выгрузка.

**Ключевые объекты:**
- **DRIVER_OBJECT** — описывает загруженный драйвер (его процедуры);
- **DEVICE_OBJECT** — описывает устройство (их может быть несколько у драйвера); образуют **стек устройств**;
- **FILE_OBJECT** — описывает открытый экземпляр устройства или файла (создаётся при `CreateFile`);
- **IRP** (I/O Request Packet) — пакет запроса ввода-вывода, который диспетчер проводит по стеку устройств.

Модели: **WDM** (классическая), **KMDF/UMDF** (Windows Driver Frameworks, проще и безопаснее).
</div>

## Назначение драйверов

- Управление **устройствами** (диск, сеть, видео, USB).
- **Файловые системы** и их фильтры.
- **Сетевые протоколы**.
- **Фильтры** (антивирусы, шифрование, мониторинг).
- Предоставление служб ядра приложениям.

Драйвер работает в **режиме ядра**, поэтому его ошибка роняет систему (BSOD). Типы: аппаратные (**function driver**), **фильтры** (верхние и нижние), **шинные** (bus driver), программные (без устройства).

## Модели драйверов

| Модель | Описание |
|---|---|
| **WDM** (Windows Driver Model) | Классическая: прямая работа с IRP, PnP, питанием. Гибко, но сложно и чревато ошибками |
| **KMDF** (Kernel-Mode Driver Framework) | Каркас поверх WDM: берёт на себя PnP, питание, очереди IRP. Проще и надёжнее |
| **UMDF** (User-Mode Driver Framework) | Драйвер в **пользовательском** режиме: сбой не роняет систему (принтеры, USB-гаджеты) |

## Структура драйвера (точки входа)

```c
#include <ntddk.h>

// диспетчерская процедура
NTSTATUS DispatchCreateClose(PDEVICE_OBJECT dev, PIRP irp) {
    irp->IoStatus.Status = STATUS_SUCCESS;
    irp->IoStatus.Information = 0;
    IoCompleteRequest(irp, IO_NO_INCREMENT);   // завершить запрос
    return STATUS_SUCCESS;
}

NTSTATUS DispatchRead(PDEVICE_OBJECT dev, PIRP irp) {
    PIO_STACK_LOCATION sp = IoGetCurrentIrpStackLocation(irp);
    ULONG len = sp->Parameters.Read.Length;
    /* заполнить буфер irp->AssociatedIrp.SystemBuffer ... */
    irp->IoStatus.Status = STATUS_SUCCESS;
    irp->IoStatus.Information = len;           // сколько байт передано
    IoCompleteRequest(irp, IO_NO_INCREMENT);
    return STATUS_SUCCESS;
}

VOID DriverUnload(PDRIVER_OBJECT drv) {
    /* удалить устройства, символические ссылки, освободить ресурсы */
}

// ГЛАВНАЯ точка входа — вызывается при загрузке драйвера
NTSTATUS DriverEntry(PDRIVER_OBJECT drv, PUNICODE_STRING regPath) {
    drv->DriverUnload = DriverUnload;
    drv->MajorFunction[IRP_MJ_CREATE] = DispatchCreateClose;
    drv->MajorFunction[IRP_MJ_CLOSE]  = DispatchCreateClose;
    drv->MajorFunction[IRP_MJ_READ]   = DispatchRead;
    // для PnP: drv->DriverExtension->AddDevice = MyAddDevice;

    // создать объект устройства и имя для доступа из пользовательского режима
    UNICODE_STRING devName, symLink;
    RtlInitUnicodeString(&devName, L"\\Device\\MyDevice");
    PDEVICE_OBJECT devObj;
    IoCreateDevice(drv, 0, &devName, FILE_DEVICE_UNKNOWN, 0, FALSE, &devObj);
    RtlInitUnicodeString(&symLink, L"\\DosDevices\\MyDevice");
    IoCreateSymbolicLink(&symLink, &devName);   // \\.\MyDevice для CreateFile
    return STATUS_SUCCESS;
}
```

| Процедура | Когда вызывается |
|---|---|
| **DriverEntry** | При загрузке драйвера. Инициализация, заполнение объекта драйвера |
| **AddDevice** | PnP-менеджер обнаружил устройство — создать для него объект устройства |
| **MajorFunction[IRP_MJ_*]** | Запрос от диспетчера ввода-вывода: `CREATE`, `CLOSE`, `READ`, `WRITE`, `DEVICE_CONTROL`, `PNP`, `POWER` |
| **ISR** | Аппаратное прерывание устройства ([вопрос 35]({{ '/q/35.html' | relative_url }})) |
| **DPC** | Отложенная обработка прерывания |
| **StartIo** | Последовательная обработка запросов к устройству |
| **Unload** | Выгрузка драйвера: очистка |

Коды запросов обрабатываются по индексу `IRP_MJ_*`; те, что драйвер не поддерживает, направляются на процедуру по умолчанию.

## Объекты ввода-вывода

### Объект драйвера (DRIVER_OBJECT)

- Создаётся диспетчером ввода-вывода при загрузке драйвера, передаётся в `DriverEntry`.
- Содержит: **массив MajorFunction** (указатели на диспетчерские процедуры), указатель `DriverUnload`, `DriverExtension->AddDevice`, список своих объектов устройств, базовый адрес и размер образа драйвера.

### Объект устройства (DEVICE_OBJECT)

- Представляет **логическое или физическое устройство**. Один драйвер может создать **несколько** объектов устройств.
- Создаётся `IoCreateDevice`. Имеет **имя** (`\Device\...`) и часто **символическую ссылку** (`\DosDevices\...` = `\\.\...`), по которой приложение открывает устройство через `CreateFile`.
- **Расширение устройства (DeviceExtension)** — область памяти драйвера для хранения состояния этого устройства.

### Стек устройств

Для одного физического устройства строится **стек объектов устройств** разных драйверов:

<pre class="diagram">
  Приложение → CreateFile/ReadFile
        │ IRP
        ▼
 ┌─────────────────┐  верхний фильтр (напр. шифрование)
 │ Filter DO       │
 ├─────────────────┤  функциональный драйвер (FDO)
 │ Function DO     │
 ├─────────────────┤  нижний фильтр
 │ Lower Filter DO │
 ├─────────────────┤  шинный драйвер (PDO)
 │ Bus / Physical  │
 └─────────────────┘
        │
     Оборудование
</pre>

IRP проходит сверху вниз; каждый драйвер обрабатывает свой уровень и передаёт запрос ниже (`IoCallDriver`) или завершает (`IoCompleteRequest`).

### Объект файла (FILE_OBJECT)

- Создаётся при **`CreateFile`** (открытии устройства или файла) — по одному на каждое открытие.
- Представляет **открытый экземпляр**: текущую позицию, режим доступа, указатель на объект устройства.
- Передаётся драйверу в IRP (`sp->FileObject`), так драйвер отличает разные сеансы работы с устройством.

### Пакет запроса ввода-вывода (IRP)

- **IRP** — структура, описывающая один запрос ввода-вывода (чтение, запись, управление).
- Создаётся диспетчером ввода-вывода при запросе от приложения; содержит **стек расположений (IO_STACK_LOCATION)** — по одному на каждый драйвер в стеке устройств.
- В стековом расположении: **MajorFunction** (тип операции), параметры (длина, смещение, код IOCTL), указатель на FILE_OBJECT.
- Буферы: `AssociatedIrp.SystemBuffer` (буферизованный ввод-вывод), `MdlAddress` (прямой), `UserBuffer`.
- Завершение: `IoCompleteRequest` заполняет `IoStatus` (статус и число байт) и возвращает результат вверх.

## Взаимосвязь объектов

<pre class="diagram">
 DRIVER_OBJECT ──┬──► DEVICE_OBJECT ──► DEVICE_OBJECT (стек)
 (один драйвер)  │     (устройства)         │
   MajorFunction │                          ▼
   Unload        │                     DeviceExtension (состояние)
   AddDevice     │
                 ▼
            обрабатывает IRP ◄── FILE_OBJECT (открытый экземпляр)
                 ▲
            приложение: CreateFile → FILE_OBJECT,
                        ReadFile  → IRP
</pre>

- **Один DRIVER_OBJECT** → управляет **несколькими DEVICE_OBJECT**.
- Каждое открытие устройства приложением → **FILE_OBJECT**.
- Каждая операция → **IRP**, который диспетчер направляет диспетчерской процедуре драйвера через его DRIVER_OBJECT и целевой DEVICE_OBJECT.

## Инструменты

Сборка — **WDK** (Windows Driver Kit). Установка/загрузка — `sc create`, INF-файлы, `DevCon`. Отладка — WinDbg ([вопрос 33]({{ '/q/33.html' | relative_url }})), **Driver Verifier**. Подпись драйверов обязательна в x64.
