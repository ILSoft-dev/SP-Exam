<div class="tldr" markdown="1">
**Типы процессов UNIX:**
- **системные** — часть ядра или запускаются при загрузке: `init`/`systemd` (PID 1), потоки ядра `kthreadd`, `kswapd`;
- **демоны** — фоновые службы без терминала: `sshd`, `cron`, `httpd`;
- **прикладные (пользовательские)** — запущены пользователем, интерактивные (переднего плана) или фоновые.

**Атрибуты процесса:** **PID**, **PPID**, **реальные и эффективные UID/GID**, **приоритет** (`nice`), **группа процессов (PGID)** и **сеанс (SID)**, управляющий терминал, текущий и корневой каталоги, **umask**, таблица открытых файлов, **окружение**, обработчики сигналов, лимиты ресурсов.

**Создание:** **`fork()`** создаёт копию процесса. Родителю возвращается **PID потомка**, потомку — **0**, при ошибке −1. Память копируется лениво (**copy-on-write**).

**Перегрузка (замена программы):** семейство **`exec`** (`execl`, `execv`, `execle`, `execve`, `execlp`, `execvp`) загружает новую программу **в тот же процесс**: PID и открытые файлы сохраняются.

**Завершение:** `exit(status)` / `return` из `main` / сигнал. Родитель получает статус через **`wait`/`waitpid`**. Пока родитель не вызвал `wait`, потомок остаётся **зомби**. Процесс-**сирота** усыновляется `init`.
</div>

## Типы процессов

| Тип | Описание | Примеры |
|---|---|---|
| **Системные** | Создаются ядром, выполняют функции ОС | PID 0 (swapper/idle), PID 1 **`init`** или **`systemd`**, `kthreadd`, `kswapd`, `ksoftirqd` |
| **Демоны** | Фоновые, без управляющего терминала, обычно запускаются при загрузке | `sshd`, `cron`, `syslogd`, `nginx` |
| **Прикладные** | Запущены пользователем из оболочки | `bash`, `vim`, `gcc` |
| — переднего плана | Связаны с терминалом, получают ввод с клавиатуры | `top` |
| — фоновые | Запущены с `&`, не читают с терминала | `make &` |

**Создание демона:** `fork()` → родитель завершается → `setsid()` (новый сеанс без терминала) → `chdir("/")` → `umask(0)` → закрыть стандартные дескрипторы.

## Атрибуты процесса

| Атрибут | Получить / изменить |
|---|---|
| **PID** — идентификатор | `getpid()` |
| **PPID** — идентификатор родителя | `getppid()` |
| **RUID, RGID** — кто запустил | `getuid()`, `getgid()` |
| **EUID, EGID** — с какими правами работает | `geteuid()`, `setuid()` |
| **Приоритет, nice** (−20…19) | `nice()`, `setpriority()`, `getpriority()` |
| **Группа процессов (PGID)** — задание оболочки | `getpgrp()`, `setpgid()` |
| **Сеанс (SID)** и управляющий терминал | `getsid()`, `setsid()` |
| **Текущий каталог, корневой каталог** | `chdir()`, `chroot()` |
| **umask** | `umask()` |
| **Окружение** | `environ`, `getenv()`, `setenv()` |
| **Лимиты ресурсов** | `getrlimit()`, `setrlimit()`, `ulimit` |
| **Таблица дескрипторов**, обработчики сигналов, маска сигналов | `open`, `sigaction`, `sigprocmask` |
| **Состояние** | `R`, `S`, `D`, `T`, `Z` в `ps` |

Команды: `ps -ef`, `ps aux`, `pstree`, `top`, `htop`, каталог `/proc/<PID>/`.

## Создание процесса: fork

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    int x = 10;
    pid_t pid = fork();
    if (pid == -1) { perror("fork"); return 1; }
    if (pid == 0) {                       // потомок
        x++;
        printf("потомок: PID=%d PPID=%d x=%d\n", getpid(), getppid(), x);
        _exit(7);
    }
    // родитель
    int status;
    waitpid(pid, &status, 0);
    if (WIFEXITED(status))
        printf("родитель: потомок %d завершился с кодом %d, x=%d\n",
               pid, WEXITSTATUS(status), x);  // x = 10: память раздельная
    return 0;
}
```

**Что наследует потомок:** копию адресного пространства (copy-on-write), **открытые дескрипторы** (с общей позицией), UID/GID, окружение, текущий каталог, umask, обработчики сигналов, приоритет.

**Что отличается:** PID, PPID, возвращаемое `fork` значение, ожидающие сигналы, блокировки файлов, учёт времени.

**copy-on-write:** страницы не копируются сразу. Они помечаются «только для чтения» и копируются при первой записи. Поэтому `fork` + `exec` выполняется быстро. Есть также `vfork()` (без копирования, потомок обязан сразу вызвать `exec`) и `posix_spawn()`.

## Перегрузка процесса: exec

`exec` **заменяет** код, данные, кучу и стек текущего процесса новой программой. **PID не меняется**, открытые дескрипторы сохраняются (кроме помеченных `FD_CLOEXEC`). При успехе `exec` **не возвращает управление**.

| Функция | Аргументы | Поиск по PATH | Окружение |
|---|---|---|---|
| `execl(path, arg0, ..., NULL)` | Список (**l**ist) | Нет | Текущее |
| `execv(path, argv[])` | Массив (**v**ector) | Нет | Текущее |
| `execle(path, arg0, ..., NULL, envp)` | Список | Нет | Своё (**e**nv) |
| `execve(path, argv, envp)` | Массив | Нет | Своё — **единственный настоящий системный вызов** |
| `execlp(file, arg0, ..., NULL)` | Список | Да (**p**ath) | Текущее |
| `execvp(file, argv)` | Массив | Да | Текущее |

**Как оболочка запускает команду** `ls -l`:

```c
pid_t pid = fork();
if (pid == 0) {
    execlp("ls", "ls", "-l", (char *)NULL);
    perror("exec");            // сюда попадаем только при ошибке
    _exit(127);
}
waitpid(pid, NULL, 0);          // для фонового запуска (&) — без ожидания
```

## Завершение процесса

**Способы:**
- `return` из `main` или вызов **`exit(status)`** — вызывает обработчики `atexit`, сбрасывает буферы `stdio`, затем `_exit`;
- **`_exit(status)`** — немедленный выход без сброса буферов (используется в потомке после `fork`);
- получение **сигнала** (`SIGKILL`, `SIGSEGV`, `SIGINT`…);
- `abort()` → `SIGABRT`.

**Что делает ядро:** закрывает все дескрипторы, освобождает память, отправляет родителю **`SIGCHLD`**, сохраняет **код завершения** и учётную информацию. Процесс становится **зомби**.

**Ожидание потомка:**
```c
int status;
pid_t p = wait(&status);               // любого потомка
p = waitpid(pid, &status, WNOHANG);    // конкретного, без блокировки
if (WIFEXITED(status))   printf("код %d\n", WEXITSTATUS(status));
if (WIFSIGNALED(status)) printf("сигнал %d\n", WTERMSIG(status));
```

| Ситуация | Что происходит |
|---|---|
| **Зомби** (`Z`, defunct) | Потомок завершился, а родитель ещё не вызвал `wait`. Занимает запись в таблице процессов. Убирается вызовом `wait` или обработкой `SIGCHLD` (либо `signal(SIGCHLD, SIG_IGN)`) |
| **Сирота** | Родитель завершился раньше потомка. Потомка «усыновляет» **init/systemd** (PID 1) или subreaper, который и вызывает `wait` |

Принудительное завершение: `kill(pid, SIGTERM)` (вежливо), `kill(pid, SIGKILL)` (нельзя перехватить). Команды `kill`, `killall`, `pkill`.
