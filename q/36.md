<div class="tldr" markdown="1">
**Пулы памяти (pools)** — это **динамическая память режима ядра**, аналог кучи для драйверов и компонентов ОС. Ядро выделяет из пулов структуры данных переменного размера.

Два основных вида:
- **Пул подкачиваемой памяти (paged pool)** — может быть **выгружен на диск**, поэтому доступен **только на IRQL < DISPATCH_LEVEL** (PASSIVE/APC), где допустимы страничные сбои;
- **Пул неподкачиваемой памяти (nonpaged pool)** — **всегда в физической ОЗУ**, доступен на **любом IRQL** ([вопрос 37]({{ '/q/37.html' | relative_url }})).

**Пул подкачиваемой памяти** используется для данных, к которым обращаются **только на низком IRQL**: объекты, которые могут «подождать», большие редкие структуры. Он **дешевле** для системы, потому что при нехватке памяти его страницы можно выгрузить.

Выделение: **`ExAllocatePoolWithTag(PagedPool, size, tag)`** (современно — `ExAllocatePool2`), освобождение — `ExFreePoolWithTag`. Каждое выделение помечается **тегом** (4 символа) для диагностики утечек.

Пулы — **ограниченный ресурс**. Их исчерпание или повреждение ведёт к сбоям (`BSOD`); утечки ищут по тегам (`!poolused`, Driver Verifier, Poolmon).
</div>

## Память режима ядра

Ядру и драйверам тоже нужна **динамическая память** для структур переменного размера (списки, буферы, объекты). Её источники:

| Источник | Что это |
|---|---|
| **Пулы (pools)** | Динамическая память ядра общего назначения (аналог кучи) |
| **Системный кеш** | Кеширование файлов |
| **Таблицы страниц, PFN** | Служебные структуры памяти |
| **Стеки режима ядра** | По стеку на каждый поток |

Пулы — это части **системного адресного пространства** (верхняя половина ВАП, общая для всех процессов, [вопрос 10]({{ '/q/10.html' | relative_url }})).

## Виды пулов

| Пул | В памяти | Доступен на IRQL | Назначение |
|---|---|---|---|
| **Paged pool** (подкачиваемый) | Может быть выгружен на диск | Только **< DISPATCH_LEVEL** | Данные, используемые на низком IRQL |
| **Nonpaged pool** (неподкачиваемый) | Всегда в ОЗУ | **Любой**, в том числе DIRQL | Данные, нужные ISR/DPC ([вопрос 37]({{ '/q/37.html' | relative_url }})) |
| **Session pool** | Подкачиваемый, на сеанс | PASSIVE | Данные графики/сеанса (win32k) |
| **Special pool** | Особый | — | Диагностика повреждений (Driver Verifier) |

## Пул подкачиваемой памяти (paged pool)

- Содержимое может быть **вытеснено на диск** (в файл подкачки), как обычная виртуальная память.
- Поэтому обращение к нему может вызвать **страничный сбой**, а это допустимо **только на IRQL ниже DISPATCH_LEVEL**.

<div class="warn" markdown="1">
Нельзя обращаться к подкачиваемому пулу из **ISR или DPC** (высокий IRQL): если нужная страница окажется выгруженной, возникнет страничный сбой на высоком IRQL → **«синий экран»** `IRQL_NOT_LESS_OR_EQUAL`. Для таких данных нужен **неподкачиваемый** пул.
</div>

- **Когда использовать:** структуры, к которым обращается только код на PASSIVE/APC_LEVEL — диспетчерские процедуры драйвера, редко используемые или большие объекты.
- **Преимущество:** экономит физическую память — при её нехватке страницы подкачиваемого пула можно выгрузить.
- **Размер** ограничен (настраивается, зависит от объёма ОЗУ и разрядности). Раньше был узким местом 32-битных систем; в 64-битных пулы намного больше.

## Выделение и освобождение

```c
#include <ntddk.h>

#define MY_TAG 'GATm'    // тег 'mTAG' (пишется в обратном порядке)

// выделить из подкачиваемого пула
PVOID buf = ExAllocatePoolWithTag(PagedPool, 1024, MY_TAG);   // старый API
// современно (Windows 10 2004+):
// PVOID buf = ExAllocatePool2(POOL_FLAG_PAGED, 1024, MY_TAG);
if (buf == NULL) { /* нет памяти */ return STATUS_INSUFFICIENT_RESOURCES; }

/* использовать buf только на IRQL < DISPATCH_LEVEL */

ExFreePoolWithTag(buf, MY_TAG);   // обязательно освободить
```

Типы пула в `POOL_TYPE`: `PagedPool`, `NonPagedPool` (устар., теперь `NonPagedPoolNx` — без права выполнения), `NonPagedPoolNx`, `PagedPoolCacheAligned`.

### Теги пула

- **Тег** — 4 символа ASCII, которые помечают каждое выделение.
- Назначение: **диагностика** — по тегу видно, **какой драйвер или подсистема** сколько памяти занимает и где **утечка**.
- Просмотр: команда отладчика `!poolused`, `!pooltag`, утилита **PoolMon** (из WDK), Driver Verifier.

## Исчерпание и ошибки пула

- Пул — **ограниченный** ресурс. Утечка (выделили и не освободили) постепенно его исчерпывает → система замедляется и падает.
- Типичные ошибки драйверов: **утечка пула**, **запись за границу** выделенного блока (повреждение соседних данных), **двойное освобождение**, обращение к уже освобождённой памяти.
- Диагностика: **Driver Verifier** (special pool ловит выход за границу сразу), **PoolMon**, анализ дампа `!analyze -v`, BSOD-коды `BAD_POOL_HEADER`, `BAD_POOL_CALLER`, `DRIVER_CORRUPTED_EXPOOL`.

## Сравнение (подробно в [вопросе 37]({{ '/q/37.html' | relative_url }}))

| | Подкачиваемый пул | Неподкачиваемый пул |
|---|---|---|
| Выгрузка на диск | Да | **Нет** |
| IRQL доступа | < DISPATCH_LEVEL | Любой |
| Нагрузка на ОЗУ | Меньше | Больше (всегда в ОЗУ) |
| Для ISR/DPC | **Нельзя** | Можно |
| Размер | Больше | Строго ограничен |
