<div class="tldr" markdown="1">
Windows реализует **вытесняющую многозадачность** на основе **потоков**. ОС по прерыванию таймера и по приоритетам сама отбирает процессор у потока.

**Процесс** в Windows — **контейнер ресурсов**, он не выполняется сам по себе. Содержит: закрытое **виртуальное адресное пространство**, **таблицу дескрипторов (HANDLE)** объектов ядра, **маркер доступа** (пользователь, группы, привилегии), базовый приоритет, загруженный EXE и DLL и **минимум один поток**. Описывается объектом **EPROCESS**.

**Поток** — **единица планирования**. Содержит: **контекст** (регистры), **два стека** (пользовательский и режима ядра), **TLS**, приоритет, маску привязки к процессорам, блок **TEB**. Описывается объектом **ETHREAD**/`KTHREAD`.

**Контекст потока** — состояние процессора для возобновления выполнения: регистры, счётчик команд, указатель стека, флаги. Доступен через структуру **`CONTEXT`** и функции `GetThreadContext` / `SetThreadContext` (поток нужно приостановить). При переключении потоков ОС сохраняет и восстанавливает контекст.

**Волокно (fiber)** — «лёгкий поток» с кооперативным переключением вручную внутри потока.
</div>

## Многозадачность в Windows

- **Вытесняющая, на уровне потоков.** Планировщик вызывается по прерыванию таймера (квант), при разблокировке более приоритетного потока, при изменении приоритета.
- **Абсолютные приоритеты** (32 уровня) + **Round Robin** внутри уровня ([вопрос 12]({{ '/q/12.html' | relative_url }})).
- На многоядерных системах потоки одного процесса могут выполняться **параллельно** на разных ядрах.
- Исторически: Windows 3.x — **кооперативная** многозадачность (поток сам отдавал процессор), Windows 95 — вытесняющая для 32-битных программ, Windows NT — полностью вытесняющая.

## Процесс как контейнер ресурсов

| Компонент процесса | Описание |
|---|---|
| **Виртуальное адресное пространство** | Закрытое, изолированное ([вопрос 10]({{ '/q/10.html' | relative_url }})) |
| **Таблица дескрипторов (HANDLE)** | Ссылки на объекты ядра: файлы, события, потоки, мьютексы |
| **Маркер доступа (access token)** | SID пользователя и групп, привилегии, уровень целостности |
| **Базовый приоритет (класс)** | Idle, Normal, High, Realtime… |
| **Загруженный образ** | EXE и подключённые DLL |
| **Идентификатор (PID)**, родитель | |
| **Потоки** | Как минимум один (главный) |
| **PEB** (Process Environment Block) | Пользовательская структура: параметры, список модулей, куча |

**Дескриптор (HANDLE)** — индекс в таблице дескрипторов процесса, непрозрачная ссылка на объект ядра. Дескрипторы закрываются `CloseHandle`, наследуются потомком (если помечены наследуемыми) или дублируются `DuplicateHandle`.

## Поток как единица планирования

| Компонент потока | Описание |
|---|---|
| **Контекст** | Регистры, PC, SP, флаги |
| **Стек пользовательского режима** | Для кода приложения (по умолчанию 1 МБ) |
| **Стек режима ядра** | Для выполнения системных вызовов |
| **TLS** (Thread Local Storage) | Данные, приватные для потока |
| **Приоритет** | Базовый + динамический |
| **Маска привязки (affinity)** | На каких процессорах может выполняться |
| **TEB** (Thread Environment Block) | Пользовательская структура потока (адресуется через FS/GS) |
| **Состояние** | Ready, Running, Waiting, Standby, Terminated |

## Объекты EPROCESS и ETHREAD

- **EPROCESS** — структура ядра, описывающая процесс: `KPROCESS` (для планирования), PID, таблица дескрипторов, указатель на каталог страниц, маркер доступа, список потоков, указатель на PEB.
- **ETHREAD** (включает `KTHREAD`) — структура потока: контекст, состояние, приоритет, стеки, адрес стартовой функции, указатель на TEB, принадлежность процессу.
- Диспетчер объектов создаёт их при `CreateProcess` и `CreateThread`.

## Контекст потока

**Контекст** — всё состояние процессора, нужное для продолжения выполнения потока с прерванного места.

```c
CONTEXT ctx = { 0 };
ctx.ContextFlags = CONTEXT_FULL;         // какие группы регистров нужны
SuspendThread(hThread);                  // поток нужно остановить
GetThreadContext(hThread, &ctx);
printf("RIP=%p RSP=%p RAX=%llu\n",
       (void*)ctx.Rip, (void*)ctx.Rsp, ctx.Rax);
ctx.Rip = (DWORD64)newFunc;              // можно изменить счётчик команд
SetThreadContext(hThread, &ctx);
ResumeThread(hThread);
```

- Структура **`CONTEXT`** зависит от архитектуры (x86, x64, ARM). Содержит регистры общего назначения, сегментные, флаги, указатели стека и команд, регистры FPU/SSE.
- `ContextFlags` выбирает, какие группы регистров читать или писать (`CONTEXT_CONTROL`, `CONTEXT_INTEGER`, `CONTEXT_FLOATING_POINT`).
- Используется отладчиками, профилировщиками, обработчиками исключений, при перехвате функций.

### Переключение контекста

1. Прерывание (таймер, системный вызов, ожидание) → режим ядра.
2. Ядро сохраняет контекст текущего потока в его `KTHREAD`.
3. Планировщик выбирает следующий поток (наивысший приоритет, затем RR).
4. Восстанавливается его контекст. Если это поток **другого процесса**, переключается адресное пространство (регистр CR3, возможен сброс TLB).
5. Возврат в пользовательский режим нового потока.

Переключение между потоками одного процесса дешевле: адресное пространство не меняется.

## Волокна (fibers)

- **Волокно** — единица выполнения, которую планирует **само приложение**, а не ОС. Переключение **кооперативное**, вручную.
- Создание: `ConvertThreadToFiber`, `CreateFiber`, переключение `SwitchToFiber`, данные — `FlsAlloc`.
- В одном потоке может быть много волокон, но одновременно выполняется одно.
- Применение: перенос приложений с кооперативной многозадачностью, планировщики в СУБД, корутины.
- **Пулы потоков** (`CreateThreadpoolWork`, `QueueUserWorkItem`) — более современный способ выполнять много мелких задач без создания потоков вручную.

## Просмотр

Диспетчер задач, **Process Explorer** и **Process Hacker** показывают процессы, их потоки, дескрипторы, приоритеты, маркеры доступа и загруженные DLL. В отладчике WinDbg — команды `!process`, `!thread`.
