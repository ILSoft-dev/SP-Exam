<div class="tldr" markdown="1">
В программе написано «Сообщества, семафоры, разделяемая память» — это опечатка, имеются в виду **сообщения** (очереди сообщений). Это три механизма **System V IPC**, у них общая схема:
- **ключ** (`key_t`, получается из пути функцией `ftok`, или `IPC_PRIVATE`) → вызов `*get` возвращает **идентификатор** объекта;
- объект живёт в ядре **независимо от процессов**, пока его явно не удалят (`*ctl(..., IPC_RMID)`, команда `ipcrm`);
- у объекта есть **права доступа** как у файла. Просмотр: `ipcs`.

| Механизм | Вызовы | Назначение |
|---|---|---|
| **Очереди сообщений** | `msgget`, `msgsnd`, `msgrcv`, `msgctl` | Обмен **типизированными** сообщениями, выборка по типу |
| **Семафоры** (наборы) | `semget`, `semop`, `semctl` | Синхронизация. Атомарные операции над **набором** семафоров |
| **Разделяемая память** | `shmget`, `shmat`, `shmdt`, `shmctl` | Самый быстрый обмен: общая область памяти |

Есть и современные **POSIX**-аналоги: `mq_open`, `sem_open`/`sem_init`, `shm_open` + `mmap`.

**Потоки в UNIX** — стандарт **POSIX Threads (pthreads)**: `pthread_create`, `pthread_join`, `pthread_exit`, синхронизация **`pthread_mutex_*`**, **`pthread_cond_*`**, `pthread_rwlock_*`. В Linux поток — это задача ядра, созданная `clone()` с общей памятью (NPTL, модель 1:1). Сборка: `gcc -pthread`.
</div>

## Общая схема System V IPC

```c
#include <sys/ipc.h>
key_t key = ftok("/tmp/myapp", 'A');  // ключ из пути (файл должен существовать) и символа
```

- **Ключ** — «имя» объекта, по которому разные процессы находят один и тот же объект.
- **Флаги:** `IPC_CREAT` (создать, если нет), `IPC_EXCL` (ошибка, если существует) + права (`0666`).
- **Идентификатор** — число, которое возвращает `*get` и используют остальные вызовы.
- **Управление** `*ctl`: `IPC_STAT` (информация), `IPC_SET` (права), **`IPC_RMID`** (удалить).
- Объекты **не удаляются автоматически** при завершении процессов.
- Команды: `ipcs -q -s -m`, `ipcrm -q id`.

## Очереди сообщений

```c
#include <sys/msg.h>

struct msgbuf { long mtype; char mtext[128]; };   // mtype > 0 обязателен

/* отправитель */
int q = msgget(key, IPC_CREAT | 0666);
struct msgbuf m = { .mtype = 1 };
strcpy(m.mtext, "привет");
msgsnd(q, &m, strlen(m.mtext) + 1, 0);            // размер — только mtext

/* получатель */
struct msgbuf r;
msgrcv(q, &r, sizeof r.mtext, 1, 0);              // тип 1
printf("%s\n", r.mtext);
msgctl(q, IPC_RMID, NULL);                        // удалить очередь
```

- Параметр **`msgtyp`** в `msgrcv`: **0** — первое сообщение любого типа; **> 0** — первое сообщение **этого** типа; **< 0** — сообщение с **наименьшим** типом ≤ |msgtyp| (приоритеты).
- Сохраняются **границы** сообщений (в отличие от канала).
- Флаг `IPC_NOWAIT` — не блокироваться, если очередь полна или пуста.
- Применение: клиент-сервер, где тип сообщения = PID клиента.

## Семафоры

System V создаёт **набор** семафоров, а `semop` выполняет **несколько операций атомарно**.

```c
#include <sys/sem.h>

union semun { int val; struct semid_ds *buf; unsigned short *array; };

int s = semget(key, 1, IPC_CREAT | 0666);       // набор из 1 семафора
union semun arg = { .val = 1 };
semctl(s, 0, SETVAL, arg);                       // начальное значение 1

struct sembuf P = { 0, -1, SEM_UNDO };           // номер, операция, флаги
struct sembuf V = { 0, +1, SEM_UNDO };

semop(s, &P, 1);     // P — войти в критическую секцию
/* работа с общим ресурсом */
semop(s, &V, 1);     // V — выйти
```

- `sem_op < 0` — уменьшить (ждать, если значение станет меньше 0); `> 0` — увеличить; `= 0` — ждать, пока значение не станет 0.
- **`SEM_UNDO`** — ядро отменит операцию, если процесс аварийно завершится. Это защищает от «вечно захваченного» семафора.

**POSIX-семафоры** проще:
```c
#include <semaphore.h>
sem_t *s = sem_open("/mysem", O_CREAT, 0666, 1);  // именованный (между процессами)
sem_wait(s);  /* КС */  sem_post(s);
sem_close(s); sem_unlink("/mysem");
// неименованный (между потоками или в разделяемой памяти):
sem_t s2; sem_init(&s2, 0, 1);
```

## Разделяемая память

```c
#include <sys/shm.h>

int id = shmget(key, 4096, IPC_CREAT | 0666);   // сегмент 4 КБ
char *p = shmat(id, NULL, 0);                    // подключить к адресному пространству
strcpy(p, "данные для другого процесса");        // обычный доступ к памяти
shmdt(p);                                        // отключить
shmctl(id, IPC_RMID, NULL);                      // удалить (после отключения всеми)
```

- **Самый быстрый** способ IPC: данные не копируются через ядро.
- **Синхронизацию** нужно организовать отдельно, обычно семафорами.
- Сегмент сохраняется после завершения процессов, пока его не удалят.

**POSIX:** `int fd = shm_open("/myshm", O_CREAT | O_RDWR, 0666); ftruncate(fd, 4096); void *p = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);`.

## Сравнение

| | Очередь сообщений | Семафор | Разделяемая память |
|---|---|---|---|
| Передаёт данные | Да (копирование через ядро) | Нет, только синхронизация | Да, без копирования |
| Скорость | Средняя | — | Максимальная |
| Синхронизация | Встроенная | Это и есть синхронизация | Нужна отдельная |
| Типичное использование | Клиент-сервер | Взаимное исключение, счётчики | Большие объёмы данных |

## Потоки в UNIX (POSIX Threads)

### Понятие

- **Поток** — независимый поток управления внутри процесса: свой стек, регистры, `errno`, маска сигналов, TID. **Общие**: память, дескрипторы файлов, обработчики сигналов, PID.
- В **Linux** потоки реализованы как **задачи ядра** (`clone()` с флагами `CLONE_VM | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD`), библиотека **NPTL**, модель **1:1**. `gettid()` возвращает идентификатор потока, `ps -L` показывает потоки.

### Создание и завершение

```c
#include <pthread.h>
#include <stdio.h>

#define N 4
long counter = 0;
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;

void *worker(void *arg) {
    long id = (long)arg;
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&m);
        counter++;
        pthread_mutex_unlock(&m);
    }
    printf("поток %ld готов\n", id);
    return NULL;                 // или pthread_exit(NULL)
}

int main(void) {
    pthread_t t[N];
    for (long i = 0; i < N; i++)
        pthread_create(&t[i], NULL, worker, (void *)i);
    for (int i = 0; i < N; i++)
        pthread_join(t[i], NULL);  // ждать завершения
    printf("counter = %ld\n", counter);   // ровно 400000
    return 0;
}
```
Сборка: `gcc -pthread prog.c -o prog`.

| Функция | Назначение |
|---|---|
| `pthread_create(&t, attr, func, arg)` | Создать поток |
| `pthread_join(t, &ret)` | Дождаться завершения и получить результат |
| `pthread_exit(ret)` | Завершить текущий поток |
| `pthread_detach(t)` | «Отсоединить»: ресурсы освободятся сами, `join` не нужен |
| `pthread_self()`, `pthread_equal()` | Свой идентификатор, сравнение |
| `pthread_cancel(t)` | Запрос отмены потока |
| `pthread_attr_*` | Атрибуты: размер стека, detached, политика планирования |

### Синхронизация потоков

- **Мьютексы:** `pthread_mutex_lock`/`trylock`/`unlock`. Типы: обычный, рекурсивный, с проверкой ошибок.
- **Условные переменные:** ожидание условия без активного ожидания.

```c
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t  c = PTHREAD_COND_INITIALIZER;
int ready = 0;

/* потребитель */                       /* производитель */
pthread_mutex_lock(&m);                 pthread_mutex_lock(&m);
while (!ready)                          ready = 1;
    pthread_cond_wait(&c, &m);          pthread_cond_signal(&c);
/* использовать данные */                pthread_mutex_unlock(&m);
pthread_mutex_unlock(&m);
```

`pthread_cond_wait` **атомарно** освобождает мьютекс и засыпает, а при пробуждении снова захватывает мьютекс. Условие проверяется в **цикле `while`**, потому что возможны ложные пробуждения.
- **Блокировки чтения-записи:** `pthread_rwlock_rdlock`/`wrlock`.
- **Барьеры:** `pthread_barrier_wait`. **Спин-блокировки:** `pthread_spin_lock`.
- **Семафоры** POSIX: `sem_init`/`sem_wait`/`sem_post`.

### Потоки и процессы: особенности

- `fork()` в многопоточной программе копирует **только вызвавший поток**, поэтому после `fork` безопасно сразу вызывать `exec`.
- Сигналы: обработчики общие для процесса, а маска своя у каждого потока (`pthread_sigmask`). Удобно выделить отдельный поток для `sigwait`.
- Функции должны быть **потокобезопасными** (`strtok_r` вместо `strtok`).
