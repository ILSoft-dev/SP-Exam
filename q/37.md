<div class="tldr" markdown="1">
**Пул неподкачиваемой памяти (nonpaged pool)** — память ядра, которая **всегда находится в физической ОЗУ** и никогда не выгружается на диск. Поэтому к ней можно обращаться на **любом IRQL**, в том числе из **ISR и DPC**.

Используется для данных, к которым обращается код на **высоком IRQL**: структуры драйверов, буферы DMA, объекты, с которыми работают обработчики прерываний. Это **дефицитный** ресурс (занимает физическую память), поэтому его расходуют экономно. Современный вариант — **NonPagedPoolNx** (без права выполнения кода, для защиты).

**Пул сессии (session pool)** — подкачиваемая память **для каждого сеанса** входа пользователя: данные графической подсистемы (win32k.sys), оконные структуры. Изолирует сеансы друг от друга.

**Особый пул (special pool)** — диагностический режим: каждое выделение размещается на **отдельной странице** с «охранными» страницами по краям, чтобы **мгновенно** ловить выход за границу буфера и обращение к освобождённой памяти. Включается через **Driver Verifier**.

**Тегирование пулов** — каждое выделение помечается 4-символьным **тегом**, что позволяет находить, какой драйвер течёт (**PoolMon**, `!poolused`).
</div>

## Пул неподкачиваемой памяти

- **Всегда резидентен** в физической памяти, страничных сбоев при обращении не бывает.
- Доступен на **любом IRQL**, включая DISPATCH_LEVEL и DIRQL.

| Применение | Почему неподкачиваемый |
|---|---|
| Структуры, с которыми работает **ISR** | ISR на DIRQL, подкачиваемая память недопустима |
| Данные, используемые в **DPC** | DPC на DISPATCH_LEVEL |
| **Буферы DMA** | Устройство пишет в физическую память напрямую, она не должна «уехать» |
| Объекты синхронизации ядра, списки, с которыми работают на высоком IRQL | — |

```c
PVOID buf = ExAllocatePoolWithTag(NonPagedPoolNx, 512, 'DIRm');
// современно: ExAllocatePool2(POOL_FLAG_NON_PAGED, 512, 'DIRm');
/* к buf можно обращаться из ISR и DPC */
ExFreePoolWithTag(buf, 'DIRm');
```

<div class="tip" markdown="1">
**NonPagedPoolNx** (No eXecute) — неподкачиваемый пул **без права выполнения** кода. С Windows 8 рекомендуется именно он: обычный `NonPagedPool` позволял выполнять код из данных, чем пользовались эксплойты. Теперь `NonPagedPool` = `NonPagedPoolNx`.
</div>

### Неподкачиваемый vs подкачиваемый

| | Неподкачиваемый | Подкачиваемый ([вопрос 36]({{ '/q/36.html' | relative_url }})) |
|---|---|---|
| Выгрузка на диск | **Никогда** | Может быть выгружен |
| IRQL доступа | **Любой** (ISR, DPC) | Только < DISPATCH_LEVEL |
| Нагрузка на физ. память | Высокая (всегда в ОЗУ) | Низкая |
| Дефицитность | Высокая, расходуется экономно | Меньше |
| Пример данных | Буферы DMA, структуры для ISR | Редкие большие объекты |

## Пул сессии (session pool)

- **Сеанс (session)** — набор процессов одного входа в систему (консоль, каждое подключение по RDP). У каждого сеанса своё пространство для графической подсистемы.
- **Пул сессии** — подкачиваемая память, выделяемая **в контексте сеанса**: оконные объекты, структуры **win32k.sys**, GDI-объекты.
- **Изоляция:** данные одного сеанса не видны другим, что важно для серверов терминалов (много пользователей одновременно).
- Выделяется с флагом сеансового пула; учитывается отдельно для каждого сеанса.

## Особый пул (special pool)

**Особый пул** — диагностический механизм поиска ошибок работы с пулом. Включается **Driver Verifier** для выбранного драйвера.

Как работает:
- каждое выделение помещается на **отдельную страницу**;
- с одной стороны выделения ставится **недоступная «охранная» (guard) страница**;
- блок прижимается к **концу** страницы, поэтому **выход за границу** (переполнение буфера) немедленно вызывает страничный сбой → BSOD **точно в месте ошибки**, а не позже;
- после освобождения страница помечается недоступной, поэтому **обращение к освобождённой памяти** тоже ловится сразу.

<pre class="diagram">
┌───────────┬──────────────┬───────────┐
│ охранная  │  ...  данные │ охранная  │
│ страница  │ (прижаты к   │ страница  │
│ (нет дост)│  границе) ▸▸▸│ (нет дост)│
└───────────┴──────────────┴───────────┘
 выход за границу → мгновенный сбой
</pre>

- ➕ Ошибки ловятся **сразу**, а не как «плавающие» сбои через время.
- ➖ Очень **расточителен** по памяти (страница на каждое выделение), поэтому применяется только при отладке.

## Тегирование пулов и диагностика

- **Тег** (`ULONG`, 4 символа) задаётся в `ExAllocatePoolWithTag`. По соглашению пишется «задом наперёд» (`'FooM'` → читается `MooF`).
- Позволяет понять, **кто** занял память и **где утечка**.

| Инструмент | Что показывает |
|---|---|
| **PoolMon** (`poolmon.exe`, WDK) | Таблица по тегам: сколько выделений, байт, прирост. Видно растущий тег = утечка |
| `!poolused` (WinDbg) | Использование пула по тегам из дампа или вживую |
| `!pool addr`, `!pooltag` | Разбор конкретного блока пула, расшифровка тега |
| **Driver Verifier** | Проверки пула: special pool, отслеживание утечек, слежение за IRQL |
| Счётчики PerfMon | «Paged Pool Bytes», «Nonpaged Pool Bytes» |

**Типичные BSOD, связанные с пулом:** `BAD_POOL_HEADER`, `BAD_POOL_CALLER`, `PAGE_FAULT_IN_NONPAGED_AREA`, `DRIVER_CORRUPTED_EXPOOL`.
