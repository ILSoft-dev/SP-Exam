<div class="tldr" markdown="1">
**Страничная организация.** Адресное пространство процесса делится на **страницы** фиксированного размера (обычно **4 КБ**), физическая память — на **кадры (фреймы)** того же размера. **Таблица страниц** процесса отображает номер страницы в номер кадра и хранит биты **присутствия, обращения, модификации, защиты**. Адрес = **(номер страницы, смещение)** → физ. адрес = **кадр × размер + смещение**. Отсутствие страницы вызывает **страничное прерывание**. Ускорение — **TLB**, экономия памяти на таблицах — **многоуровневые таблицы**. ➕ Нет внешней фрагментации. ➖ Внутренняя фрагментация, страница не отражает логику программы.

**Сегментация.** Адресное пространство делится на **сегменты** переменной длины — логические части программы: код, данные, стек. Адрес = **(номер сегмента, смещение)**. **Таблица сегментов** хранит **базу, предел, права**. Физ. адрес = **база + смещение**, если смещение < предела. ➕ Логическая структура, удобная защита и совместное использование. ➖ Внешняя фрагментация.

**Сегментно-страничная** организация объединяет оба подхода: сегменты делятся на страницы (Intel x86, MULTICS).
</div>

## Страничная организация

<pre class="diagram">
Виртуальный адрес (32 бита, стр. 4 КБ)
┌──────────────────────┬────────────┐
│ номер страницы (20 б)│ смещ. (12б)│
└──────────┬───────────┴─────┬──────┘
           ▼                 │
   Таблица страниц[p]        │
   → кадр f, P=1?            │
           ▼                 ▼
┌──────────────────────┬────────────┐
│     номер кадра f    │  смещение  │
└──────────────────────┴────────────┘
Физический адрес
</pre>

### Запись таблицы страниц (PTE)

| Поле | Назначение |
|---|---|
| Номер кадра | Где страница в физической памяти |
| **P** (Present) | Страница в ОЗУ (1) или на диске (0) |
| **R / A** (Accessed) | Было обращение. Используется алгоритмами замещения |
| **M / D** (Dirty) | Страница изменена, при вытеснении её нужно сохранить |
| **R/W, U/S, NX** | Запись разрешена, доступ из пользовательского режима, запрет выполнения |

### Пример

Страница 4096 Б, виртуальный адрес **8200**: страница = 8200 div 4096 = **2**, смещение = **8**. Страница 2 → кадр **5**. Физический адрес = 5 · 4096 + 8 = **20 488**.

### Страничное прерывание (page fault)

1. MMU видит P = 0 → **исключение**.
2. ОС находит свободный кадр. Если его нет, выбирает **жертву** по алгоритму замещения (LRU, «часы»…) и при M = 1 записывает её на диск.
3. Страница читается с диска, таблица обновляется.
4. Команда, вызвавшая прерывание, **выполняется повторно**.

### TLB и многоуровневые таблицы

- **TLB (Translation Lookaside Buffer)** — ассоциативный кеш в процессоре, хранит недавние преобразования «страница → кадр». Попадание — 98–99 %. При переключении процессов TLB сбрасывается, если нет тегов ASID/PCID.
- **Многоуровневые таблицы:** 32 бита при 4 КБ страницах дают 2²⁰ записей = 4 МБ на процесс. Поэтому адрес делится на **индекс каталога (10) + индекс таблицы (10) + смещение (12)** и хранятся только нужные таблицы. x86-64 использует **4 или 5 уровней** (PML4 → PDPT → PD → PT).
- **Инвертированная таблица страниц** — одна запись на каждый **кадр** с поиском по хешу. Применялась в PowerPC и IA-64.

### Достоинства и недостатки

- ➕ Нет внешней фрагментации, простое распределение (любой свободный кадр), эффективная подкачка.
- ➖ **Внутренняя фрагментация**: в среднем ½ страницы на процесс.
- ➖ Затраты памяти на таблицы и времени на преобразование.
- ➖ Страницы «не видны» программисту и не соответствуют логической структуре.

## Сегментация

<pre class="diagram">
(сегмент s, смещение d)
        │
        ▼
Таблица сегментов[s] → (база, предел, права)
        │
   d < предел? ── нет ──► исключение
        │ да
        ▼
физический адрес = база + d
</pre>

### Пример

| Сегмент | База | Предел | Права |
|---|---|---|---|
| 0 — код | 1400 | 1000 | R-X |
| 1 — данные | 6300 | 400 | RW- |
| 2 — стек | 4300 | 1100 | RW- |

- (1, 53) → 53 < 400 → **6353**.
- (0, 1222) → 1222 ≥ 1000 → **ошибка защиты**.

### Особенности

- Сегменты **видны программисту и компилятору**: отдельно компилируемые модули, стек, куча.
- Каждый сегмент — **независимое адресное пространство**, сегменты могут расти независимо.
- **Защита** на уровне логических единиц: код нельзя изменять, данные нельзя выполнять.
- **Совместное использование**: несколько процессов ссылаются на один сегмент кода.
- ➖ **Внешняя фрагментация**: сегменты разного размера, нужны стратегии размещения и сжатие.
- ➖ При подкачке перемещаются **целые сегменты**.

## Сравнение

| | Страницы | Сегменты |
|---|---|---|
| Размер | Фиксированный | Переменный |
| Виден программисту | Нет | Да |
| Фрагментация | Внутренняя | Внешняя |
| Адресное пространство | Одно линейное | Несколько независимых |
| Формирование адреса | Кадр ‖ смещение (приписывание) | База + смещение (сложение) |
| Защита и разделение | По страницам | По логическим частям — естественнее |
| Цель | Большое линейное пространство без фрагментации | Логическое разбиение программы и защита |

## Сегментно-страничная организация

- Адрес = **(сегмент, страница, смещение)**.
- Дескриптор сегмента указывает на **таблицу страниц сегмента**, страница отображается на кадр.
- Объединяет логическую структуру сегментов с отсутствием внешней фрагментации у страниц.
- **Intel x86 (защищённый режим):** логический адрес (селектор : смещение) → **сегментация** → линейный адрес → **страничное преобразование** → физический адрес. Windows и Linux используют **плоскую модель**: все сегменты с базой 0 и пределом 4 ГБ, фактически работают только страницы ([вопрос 15]({{ '/q/15.html' | relative_url }})).
