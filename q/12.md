<div class="tldr" markdown="1">
**Типы планирования** (по частоте и горизонту):
- **долгосрочное** — какие задачи **допустить** в систему (уровень мультипрограммирования);
- **среднесрочное** — какие процессы **выгрузить** на диск или вернуть в память (свопинг);
- **краткосрочное (диспетчеризация)** — какому готовому потоку дать **процессор** прямо сейчас. Выполняется очень часто;
- **планирование ввода-вывода** — порядок обслуживания запросов к устройствам ([вопрос 13]({{ '/q/13.html' | relative_url }})).

Планирование бывает **вытесняющим** и **невытесняющим**.

**Алгоритмы:** **FCFS** (FIFO), **SJF** и вытесняющий **SRTF**, **Round Robin** (квантование), **приоритетное** (статические и динамические приоритеты), **многоуровневые очереди** и **очереди с обратной связью (MLFQ)**, **справедливое** планирование (fair share, CFS), **реального времени** (EDF, RMS).

**Windows:** 32 уровня приоритета, абсолютные приоритеты + RR внутри уровня, динамическое повышение. **Linux:** CFS/EEVDF для обычных задач (`nice`), `SCHED_FIFO`/`SCHED_RR` для реального времени.
</div>

| Тип | Решение | Частота |
|---|---|---|
| Долгосрочное | Допустить ли новое задание, какую «смесь» задач держать | Редко (минуты), в пакетных системах |
| Среднесрочное | Выгрузить или загрузить процесс | Средне, при нехватке памяти |
| Краткосрочное | Кому отдать процессор | Очень часто (миллисекунды) |
| Ввода-вывода | В каком порядке обслуживать запросы к устройству | При каждом запросе |

**Когда вызывается краткосрочный планировщик:** поток завершился, поток заблокировался, истёк квант (прерывание таймера), поток перешёл в готовность (возможно, с более высоким приоритетом), изменился приоритет.

**Вытесняющее** планирование — ОС может отобрать процессор (Windows NT+, Linux). **Невытесняющее** — поток отдаёт процессор сам (Windows 3.x, ранние Mac OS).

## Критерии

- **Пользовательские:** время **отклика**, время **оборота** (turnaround), **предсказуемость**, соблюдение **сроков** (deadline).
- **Системные:** **загрузка процессора**, **пропускная способность**, **справедливость**, соблюдение приоритетов, баланс ресурсов.

## Алгоритмы

### FCFS (First Come First Served, FIFO)

Невытесняющий: процессор получает пришедший первым.
- ➕ Просто. ➖ **Эффект конвоя**: короткие задачи ждут длинных.

### SJF (Shortest Job First) и SRTF

Первой выполняется задача с **наименьшим временем выполнения**. **SRTF** — вытесняющий вариант (наименьшее оставшееся время).
- ➕ **Минимальное среднее время ожидания.**
- ➖ Длительность нужно знать заранее или предсказывать (экспоненциальное усреднение прошлых интервалов). Длинные задачи могут голодать.

### Round Robin (RR, квантование)

Готовые потоки стоят в кольцевой очереди, каждый получает **квант**. Когда квант истёк, поток уходит в конец очереди.
- Слишком маленький квант даёт большие накладные расходы на переключение. Слишком большой превращает RR в FCFS.

### Приоритетное планирование

Процессор получает поток с **наивысшим приоритетом**.
- **Относительные** приоритеты (без вытеснения) и **абсолютные** (с вытеснением).
- **Статические** и **динамические** приоритеты (например, повышение после ввода-вывода).
- Проблема **голодания** → **старение (aging)**. Проблема **инверсии приоритетов** → наследование приоритета.

### Многоуровневые очереди и очереди с обратной связью (MLFQ)

- Несколько очередей с разными приоритетами и квантами.
- В **MLFQ** поток, полностью израсходовавший квант, **опускается** ниже (там квант больше), а поток, часто уходящий на ввод-вывод, остаётся наверху. Интерактивные задачи получают быстрый отклик без знания длительности.

### Справедливое планирование (fair share)

Процессор делится поровну между **пользователями или группами**, а не потоками. **CFS** в Linux распределяет время пропорционально весам.

### Планирование реального времени

- **EDF (Earliest Deadline First)** — первой выполняется задача с ближайшим сроком.
- **RMS (Rate Monotonic)** — периодическим задачам приоритет назначается по частоте: чем короче период, тем выше приоритет.

## Пример расчёта

Задачи пришли в момент 0: P1 = 6, P2 = 8, P3 = 7, P4 = 3.

| Алгоритм | Порядок | Время ожидания | Среднее |
|---|---|---|---|
| FCFS | P1 P2 P3 P4 | 0, 6, 14, 21 | **10,25** |
| SJF | P4 P1 P3 P2 | P4 = 0, P1 = 3, P3 = 9, P2 = 16 | **7** |
| RR, q = 4 | P1 P2 P3 P4 P1 P2 P3 | P1 = 17−6 = 11, P2 = 21−8 = 13, P3 = 24−7 = 17, P4 = 15−3 = 12 | **13,25** |

RR: P1 0–4, P2 4–8, P3 8–12, P4 12–15, P1 15–17, P2 17–21, P3 21–24 (в формуле: время ожидания = время завершения − длительность).

## Примеры в современных ОС

### Windows

- Планируются **потоки**. **32 уровня**: 16–31 — реальное время (фиксированные), 1–15 — переменные, 0 — поток обнуления страниц.
- **Классы приоритета процесса** (Idle, Below Normal, Normal, Above Normal, High, Realtime) + **относительный приоритет потока** (Idle … Time Critical) = базовый приоритет.
- **Абсолютные приоритеты** с вытеснением, внутри уровня — **RR**.
- **Динамическое повышение:** после ввода-вывода, для потока активного окна, при пробуждении после ожидания, для «голодающих» потоков (диспетчер настройки баланса поднимает до 15 потоки, ждущие больше ~4 с).
- **Многопроцессорность:** привязка к процессорам (affinity), идеальный процессор.
- API: `SetPriorityClass`, `SetThreadPriority`, `SetThreadAffinityMask`, `Sleep(0)`, `SwitchToThread`.

### Linux

- **Классы:** `SCHED_DEADLINE` (EDF), `SCHED_FIFO` и `SCHED_RR` (реальное время, приоритеты 1–99), `SCHED_OTHER`/`SCHED_NORMAL`, `SCHED_BATCH`, `SCHED_IDLE`.
- Обычные задачи: **CFS** (2007–2023) — выбирается задача с наименьшим **виртуальным временем выполнения** `vruntime` (красно-чёрное дерево), веса задаются **nice** (−20…+19). С ядра 6.6 — **EEVDF**.
- Очередь готовых задач для каждого ядра, балансировка нагрузки.
- API и команды: `nice`, `renice`, `chrt`, `sched_setscheduler`, `sched_setaffinity`, `taskset`.
