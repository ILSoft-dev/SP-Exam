<div class="tldr" markdown="1">
**Система управления файлами (СУФ, файловая система)** — часть ОС, которая обеспечивает **именованное хранение** данных на внешних устройствах: создание, удаление, чтение, запись, поиск, защиту и совместный доступ к файлам.

**Логическая организация файла:** **неструктурированный поток байтов** (UNIX, Windows), **последовательность записей** фиксированной или переменной длины, **индексированный файл** (записи с ключами).

**Методы доступа:** **последовательный**, **прямой (произвольный)**, **индексно-последовательный**.

**Каталоги** связывают имена файлов с их расположением и атрибутами. Структуры: одноуровневая, двухуровневая, **иерархическая (дерево или граф)**.

**Управление внешней памятью:** распределение блоков (кластеров) файлам — **непрерывное**, **связный список**, **таблица FAT**, **индексное** (inode, MFT); **учёт свободного места** — битовая карта, список свободных блоков; кеширование, отказоустойчивость (журналирование).
</div>

## Функции системы управления файлами

- **Именование** файлов и **каталоги**.
- **Программный интерфейс**: создать, открыть, читать, писать, позиционировать, закрыть, удалить.
- Отображение **логической** модели (файлы, записи) на **физическую** (блоки диска).
- **Распределение внешней памяти** и учёт свободного места.
- **Защита** (права доступа) и **совместный доступ** (блокировки файлов и записей).
- **Надёжность**: восстановление после сбоев, журналирование.
- **Производительность**: кеширование, упреждающее чтение.

**Уровни СУФ:** логический (имена, каталоги) → базовый (поиск дескриптора) → проверка прав → физический (номер блока) → драйвер устройства.

## Логическая организация файлов

| Организация | Описание | Где |
|---|---|---|
| **Неструктурированная (поток байтов)** | ОС не интерпретирует содержимое, структура — забота приложения | UNIX, Windows |
| **Последовательность записей фиксированной длины** | Позиция записи вычисляется: номер × длина | Мейнфреймы, старые СУБД |
| **Записи переменной длины** | Каждая запись хранит свою длину | — |
| **Индексированный (с ключами)** | Записи доступны по ключу, есть индекс (B-дерево) | ISAM, VSAM, базы данных |

## Методы доступа

- **Последовательный** — чтение и запись подряд, от начала к концу (как на ленте).
- **Прямой (произвольный)** — доступ к любому байту или записи по номеру: `lseek`, `SetFilePointerEx`.
- **Индексно-последовательный** — поиск по индексу, затем последовательное чтение.
- **Отображение файла в память** — `mmap`, `CreateFileMapping`/`MapViewOfFile`: файл доступен как массив в памяти.

## Атрибуты и каталоги

**Атрибуты файла:** имя, тип, размер, владелец, права, даты (создание, изменение, доступ), флаги (только чтение, скрытый, системный, архивный), расположение на диске.

**Каталог** — специальный файл со списком записей «имя → атрибуты или ссылка на дескриптор». Структуры:
- одноуровневая;
- двухуровневая (по пользователям);
- **иерархическая** — дерево с полными (абсолютными) и относительными путями;
- **граф** — с жёсткими и символическими ссылками.

**Монтирование** — подключение ФС к каталогу общего дерева (UNIX). В Windows используются буквы дисков и точки подключения.

## Управление внешней памятью (физическая организация)

**Единица выделения** — **кластер (блок)**: 2ⁿ секторов, обычно 4 КБ. Большой кластер даёт большие потери на малых файлах, маленький — большие таблицы.

| Способ размещения | Как | ➕ | ➖ | Пример |
|---|---|---|---|---|
| **Непрерывный** | Файл занимает подряд идущие блоки, хранятся начало и длина | Быстрый последовательный и прямой доступ | Внешняя фрагментация, файлу трудно расти | CD (ISO 9660) |
| **Связный список** | Каждый блок хранит номер следующего | Нет внешней фрагментации | Прямой доступ медленный | — |
| **Таблица FAT** | Номера следующих блоков вынесены в таблицу | Прямой доступ по таблице в памяти | Большая таблица, нет прав | FAT12/16/32 |
| **Индексный** | Список блоков файла в отдельной структуре | Быстрый прямой доступ | Затраты на индексные блоки | inode (ext), MFT (NTFS) |

**inode (UNIX):** атрибуты + **12 прямых** ссылок на блоки + однократно, двукратно и трёхкратно **косвенные** блоки. Каталог хранит только пары «имя → номер inode». В ext4 — **экстенты**.

**NTFS:** главная таблица файлов **MFT**, у каждого файла запись 1 КБ с атрибутами. Маленькие файлы хранятся прямо в записи MFT, большие описываются **экстентами (runs)**. Журнал — `$LogFile`.

### Учёт свободного места

- **Битовая карта** — 1 бит на блок (NTFS `$Bitmap`, ext).
- **Связный список** свободных блоков.
- **Группировка** — в первом свободном блоке хранятся номера других свободных.
- **Значение 0 в FAT**.

### Надёжность

Дублирование служебных структур (две копии FAT, `$MFTMirr`, резервные суперблоки), **журналирование** транзакций метаданных, проверка `chkdsk` и `fsck`, RAID, резервное копирование.

## Работа с файлами в программах

| Операция | WinAPI | POSIX |
|---|---|---|
| Создать / открыть | `CreateFile` | `open` (`O_CREAT`) |
| Читать / писать | `ReadFile` / `WriteFile` | `read` / `write` |
| Позиционировать | `SetFilePointerEx` | `lseek` |
| Закрыть | `CloseHandle` | `close` |
| Удалить / переименовать | `DeleteFile` / `MoveFile` | `unlink` / `rename` |
| Атрибуты | `GetFileAttributesEx` | `stat` |
| Блокировка | `LockFileEx` | `fcntl(F_SETLK)`, `flock` |
| Поиск файлов | `FindFirstFile` / `FindNextFile` | `opendir` / `readdir` |

```c
// WinAPI: копирование файла блоками
HANDLE in  = CreateFile(L"a.txt", GENERIC_READ, FILE_SHARE_READ, NULL,
                        OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);
HANDLE out = CreateFile(L"b.txt", GENERIC_WRITE, 0, NULL,
                        CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL);
char buf[4096]; DWORD n, w;
while (ReadFile(in, buf, sizeof buf, &n, NULL) && n > 0)
    WriteFile(out, buf, n, &w, NULL);
CloseHandle(in); CloseHandle(out);
```
