<div class="tldr" markdown="1">
**Перехват функции (hooking)** — внедрение своего кода, который получает управление **до или вместо** вызываемой функции API. Это штатный приём системного программирования.

**Легальные применения:** антивирусы и песочницы (контроль вызовов), **отладчики и профилировщики**, мониторинг (API Monitor, Process Monitor), трассировка, совместимость (shim-слои Windows), библиотека Microsoft **Detours**.

**NTDLL.DLL** — самая нижняя библиотека пользовательского режима. Она содержит **заглушки «родных» системных вызовов** (`NtCreateFile`, `NtReadFile`): помещают номер службы в регистр и выполняют переход в ядро (`syscall`). Все вызовы WinAPI (kernel32, user32) в итоге проходят через NTDLL — это **последняя точка пользовательского режима**, поэтому перехват на уровне NTDLL видит все обращения процесса к ядру.

**Способы перехвата в пользовательском режиме:**
- **модификация таблицы импорта (IAT hooking)** — подменить адрес функции в таблице импорта модуля;
- **сплайсинг (inline hook)** — переписать **первые байты** самой функции на переход к своему коду (так работает Detours);
- **прокси-DLL / подмена DLL** — своя библиотека вместо оригинальной;
- для доставки кода в чужой процесс — **инъекция DLL**.
Штатный механизм ОС для некоторых событий — **`SetWindowsHookEx`**.
</div>

## Понятие перехвата

Обычный вызов: `приложение → функция API`. При перехвате между ними встраивается **перехватчик (hook)**:

<pre class="diagram">
 Без перехвата:   app ──► MessageBoxW ──► результат

 С перехватом:    app ──► перехватчик ──► (лог, проверка,
                              │            изменение аргументов)
                              └──► оригинальная MessageBoxW ──► результат
</pre>

Перехватчик может **наблюдать** вызов (логировать аргументы), **изменять** аргументы или результат, **блокировать** вызов.

**Легальные применения:**
- **безопасность** — антивирусы и EDR контролируют опасные вызовы, песочницы ограничивают процесс;
- **отладка и профилирование** — трассировка вызовов, замеры времени;
- **мониторинг** — API Monitor, Process Monitor, Dependency;
- **совместимость** — **shim-слои** Windows (Application Compatibility Toolkit) правят поведение API для старых программ;
- **расширение функциональности** — наложения (overlay) в приложениях.

(Перехват используют и вредоносные программы, поэтому ОС защищает ключевые процессы: **PatchGuard** в ядре, защита целостности кода, **CFG**. Здесь материал рассматривается в учебном и защитном контексте.)

## Роль NTDLL.DLL

<pre class="diagram">
 Приложение
     │ CreateFileW
     ▼
 kernel32.dll / kernelbase.dll   (документированный Win32 API)
     │ NtCreateFile
     ▼
 NTDLL.DLL   ← последняя DLL пользовательского режима
     │  mov eax, номер_службы
     │  syscall            ─── граница режима ───
     ▼
 ntoskrnl.exe (ядро): системная служба NtCreateFile
</pre>

- **NTDLL.DLL** содержит **заглушки Native API** (`Nt*`/`Zw*`): они кладут **номер системной службы** в регистр (EAX) и выполняют инструкцию перехода в ядро (`syscall`/`sysenter`).
- Это **единственный** путь из пользовательского режима в ядро. Любой вызов kernel32/user32 рано или поздно проходит через NTDLL.
- Поэтому перехват на уровне **NTDLL** универсален: он «видит» все обращения процесса к ядру, даже если программа обошла kernel32. На этом уровне работают многие песочницы и средства мониторинга.
- NTDLL также содержит **загрузчик образов**, кучу, обработку исключений, функции времени выполнения.

## Способы перехвата в пользовательском режиме

### 1. Модификация таблицы импорта (IAT hooking)

У каждого модуля (EXE, DLL) есть **таблица адресов импорта (IAT)** — массив указателей на импортируемые функции, который заполняет загрузчик ([вопрос 32]({{ '/q/32.html' | relative_url }})).

Перехватчик находит в IAT запись нужной функции и **заменяет адрес** на свой.

- ➕ Просто, не трогает код самой функции.
- ➖ Действует только на вызовы **через IAT** данного модуля; вызовы через `GetProcAddress` или напрямую не перехватываются. Нужно обработать каждый модуль.

### 2. Сплайсинг (inline hook, splicing)

Перехватчик переписывает **первые команды самой функции** на переход (`jmp`) к своему коду. Вытесненные команды сохраняются в **трамплине (trampoline)**, через который потом вызывается оригинал.

<pre class="diagram">
 Оригинал:          Хук:
 MessageBoxW:       MessageBoxW:
   push ebp    ──►    jmp MyHook      ← первые байты заменены
   mov ebp,esp        ...
   ...            MyHook: (лог) → трамплин → оригинал
</pre>

- ➕ Перехватывает **все** вызовы функции, откуда бы они ни шли.
- ➖ Сложнее: нужно разобрать длину команд (дизассемблер длин), учесть многопоточность, снять защиту страницы (`VirtualProtect`).
- Стандартная реализация — библиотека Microsoft **Detours** (`DetourAttach`/`DetourDetach`), а также MinHook.

### 3. Прокси-DLL и подмена

- **Прокси-DLL** с тем же именем экспортирует те же функции, обрабатывает их и перенаправляет в настоящую библиотеку.
- **Порядок поиска DLL:** раньше библиотеку рядом с EXE загружали прежде системной («DLL preloading»). Сейчас это закрыто механизмами безопасного поиска DLL и KnownDLLs.

### 4. Инъекция DLL (доставка кода в чужой процесс)

Чтобы перехватчик оказался **в адресном пространстве целевого процесса**, его код (обычно DLL) туда внедряют:

| Способ | Механизм |
|---|---|
| **Через реестр** `AppInit_DLLs` | Система грузит указанные DLL во все GUI-процессы (сейчас сильно ограничено) |
| **`SetWindowsHookEx`** | Системный хук загружает DLL в процессы, получающие сообщения |
| **Удалённый поток** | В целевом процессе создаётся поток, который вызывает `LoadLibrary` (`CreateRemoteThread` + `WriteProcessMemory`) |
| **Отладочный API** | Отладчик управляет процессом |

## Штатный механизм ОС: SetWindowsHookEx

Windows предоставляет **легальный интерфейс ловушек** для событий оконной подсистемы:

```c
// глобальный хук клавиатуры
HHOOK h = SetWindowsHookEx(WH_KEYBOARD_LL, LowLevelKbProc, hInst, 0);

LRESULT CALLBACK LowLevelKbProc(int code, WPARAM wParam, LPARAM lParam) {
    if (code == HC_ACTION) { /* наблюдать нажатия */ }
    return CallNextHookEx(NULL, code, wParam, lParam);  // передать дальше по цепочке
}
```

Типы: `WH_KEYBOARD`, `WH_MOUSE`, `WH_CBT`, `WH_GETMESSAGE`, `WH_SHELL`. Это **документированный** способ наблюдать события; для глобальных хуков процедура обычно размещается в **DLL**, которую система загружает в целевые процессы. Снятие — `UnhookWindowsHookEx`.

## Инструменты

**Detours**, **MinHook** (сплайсинг), **API Monitor**, **Process Monitor**, **Spy++** (сообщения окон), **x64dbg** (отладка и анализ).
