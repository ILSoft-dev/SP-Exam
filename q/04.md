<div class="tldr" markdown="1">
За время жизни процесс (поток) проходит через несколько **состояний**:
- **выполнение** — команды выполняются процессором;
- **готовность** — процесс готов работать и ждёт только процессор;
- **ожидание (блокировка)** — процесс ждёт события: завершения ввода-вывода, освобождения ресурса, сигнала.

Также выделяют **новый (создание)** и **завершённый** процессы. В системах с подкачкой есть **приостановленные** состояния: «готовый, выгруженный» и «ожидающий, выгруженный».

**Описание процесса** — структуры данных ОС:
- **дескриптор процесса (PCB)** — идентификатор, состояние, приоритет, сведения о памяти, ресурсах, учётная информация;
- **контекст** — регистры процессора, счётчик команд, указатель стека — для возобновления выполнения.

Дескрипторы находятся в **очередях**: готовых процессов и ожидающих каждого события. **Переключение контекста** — сохранение контекста текущего процесса и загрузка контекста следующего.
</div>

## Модель с тремя состояниями

<pre class="diagram">
   создание
      │ допуск
      ▼        выбран диспетчером
 ┌─────────┐ ─────────────► ┌────────────┐
 │ГОТОВ-   │                │ ВЫПОЛНЕНИЕ │
 │НОСТЬ    │ ◄───────────── │            │
 └─────────┘  квант истёк / └────────────┘
      ▲       вытеснен           │
      │                          │ ждёт событие
      │  событие наступило  ┌──────────┐
      └─────────────────────│ ОЖИДАНИЕ │
                            └──────────┘
</pre>

| Переход | Причина |
|---|---|
| Готовность → Выполнение | Планировщик выбрал процесс |
| Выполнение → Готовность | Истёк квант или процесс вытеснен более приоритетным |
| Выполнение → Ожидание | Процесс запросил ввод-вывод, ресурс, ждёт сигнала или вызвал `Sleep` |
| Ожидание → Готовность | Событие наступило: ввод-вывод завершён, ресурс освободился |
| Выполнение → Завершён | Конец программы, `exit`, ошибка, принудительное завершение |

<div class="warn" markdown="1">
Из **ожидания** процесс **не переходит сразу в выполнение** — только в готовность. Процессор в этот момент может быть занят другим процессом.
</div>

На одном ядре в состоянии «выполнение» в каждый момент находится **не больше одного** потока. На N ядрах — не больше N.

## Модель с пятью состояниями

Добавляются:
- **Новый (создание)** — ОС создала структуры, но процесс ещё не допущен к выполнению (например, ограничено число процессов);
- **Завершённый** — процесс закончил работу, но его дескриптор ещё хранится, чтобы родитель мог получить код завершения. В UNIX это **«зомби»**.

## Приостановленные процессы (модель с 7 состояниями)

При нехватке памяти ОС может **выгрузить (swap out)** процесс на диск. Появляются состояния:
- **Готовый, приостановленный** — процесс на диске, но готов к работе после загрузки;
- **Ожидающий, приостановленный** — процесс на диске и ждёт события.

Причины приостановки: нехватка памяти, запрос пользователя (отладка, `Ctrl+Z` в UNIX → `SIGSTOP`), периодические задачи, подозрительное поведение.

### Состояния в реальных ОС

- **Linux:** `R` (выполняется или готов), `S` (прерываемый сон), `D` (непрерываемый сон, ожидание ввода-вывода), `T` (остановлен), `Z` (зомби). Посмотреть можно командами `ps aux` и `top`.
- **Windows** (состояния потока): Initialized, **Ready**, Deferred Ready, Standby (выбран для запуска на процессоре), **Running**, **Waiting**, Transition (ожидает загрузки стека ядра), **Terminated**.

## Описание процесса: дескриптор (PCB)

**Дескриптор процесса (Process Control Block, PCB)** — структура ядра, в которой ОС хранит всю информацию о процессе. В Windows это `EPROCESS` (и `ETHREAD` для потоков), в Linux — `task_struct`.

| Группа | Содержимое |
|---|---|
| **Идентификация** | PID, PPID (родитель), идентификатор пользователя и группы |
| **Состояние и планирование** | Состояние, приоритет, квант, время ожидания, указатели для очередей |
| **Память** | Адрес таблицы страниц или сегментов, границы областей |
| **Ресурсы** | Таблица открытых файлов (дескрипторов, HANDLE), объекты синхронизации |
| **Учёт** | Затраченное процессорное время, время запуска, лимиты |
| **Безопасность** | Маркер доступа, права |
| **Связи** | Родитель, потомки, потоки процесса |
| **Контекст** | Сохранённые регистры (у потоков) |

## Контекст процесса (потока)

**Контекст** — состояние процессора, нужное для продолжения выполнения с того же места:
- **счётчик команд** (EIP/RIP);
- **указатель стека** (ESP/RSP);
- **регистры общего назначения**, **регистр флагов**;
- сегментные регистры, регистры сопроцессора и SIMD;
- в Windows — структура **`CONTEXT`**, доступная функциями `GetThreadContext`/`SetThreadContext` ([вопрос 30]({{ '/q/30.html' | relative_url }})).

## Очереди процессов

ОС хранит дескрипторы в **очередях** (списках):
- **очередь готовых** процессов — одна или по одной на каждый приоритет;
- **очереди ожидания** — отдельная для каждого устройства, ресурса или события.

<pre class="diagram">
Готовые:  [P3] → [P7] → [P1]   ─► ЦП (P5)
Ждут диск:      [P2] → [P9]
Ждут клавиатуру: [P4]
</pre>

Переход между состояниями — это перенос дескриптора из одной очереди в другую.

## Переключение контекста

1. Прерывание (таймер, системный вызов, ввод-вывод) переводит процессор в режим ядра.
2. **Контекст** текущего процесса сохраняется в его дескрипторе, состояние меняется, дескриптор ставится в нужную очередь.
3. **Планировщик** выбирает следующий процесс из очереди готовых.
4. Загружаются его контекст и, если это другой процесс, его **адресное пространство** (регистр CR3, сброс TLB).
5. Управление возвращается в пользовательский режим.

Переключение — **чистые накладные расходы** (микросекунды). Переключение между потоками одного процесса дешевле: адресное пространство не меняется.
