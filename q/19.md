<div class="tldr" markdown="1">
**Типы файлов в UNIX** (первый символ в `ls -l`):
- `-` **обычный**;
- `d` **каталог**;
- `l` **символическая ссылка**;
- `c` **символьное устройство** (терминал);
- `b` **блочное устройство** (диск);
- `p` **именованный канал (FIFO)**;
- `s` **сокет**.

Принцип **«всё есть файл»**: устройства и каналы доступны через файловый интерфейс.

**Владельцы:** у каждого файла есть **владелец (UID)** и **группа (GID)**. Сменить их можно командой или вызовом `chown`.

**Права доступа:** 9 бит — **r, w, x** для трёх категорий: **владелец (u)**, **группа (g)**, **остальные (o)**. Восьмеричная запись: r = 4, w = 2, x = 1 (`chmod 754`). Дополнительные биты: **SUID** (4000), **SGID** (2000), **sticky** (1000). Права новых файлов ограничивает **umask**.

Проверка прав при доступе: если EUID = 0 → разрешено; если EUID = владелец → права владельца; если группа совпадает → права группы; иначе → права остальных.
</div>

## Типы файлов

| Символ | Тип | Пример | Создание |
|---|---|---|---|
| `-` | Обычный файл | `/etc/passwd`, `/bin/ls` | `creat`, `open(O_CREAT)` |
| `d` | Каталог | `/home` | `mkdir` |
| `l` | Символическая ссылка | `/usr/bin/python → python3` | `symlink`, `ln -s` |
| `c` | Символьное устройство | `/dev/tty`, `/dev/null` | `mknod` |
| `b` | Блочное устройство | `/dev/sda` | `mknod` |
| `p` | Именованный канал (FIFO) | `/tmp/myfifo` | `mkfifo` |
| `s` | Сокет (UNIX domain) | `/run/systemd/notify` | `socket` + `bind` |

**Жёсткая ссылка** — не отдельный тип, а ещё одно имя того же inode (`ln a b`). Счётчик ссылок виден во втором столбце `ls -l`.

**Определение типа в программе:**

```c
#include <sys/stat.h>
struct stat st;
if (lstat(path, &st) == 0) {
    if (S_ISREG(st.st_mode))  puts("обычный файл");
    else if (S_ISDIR(st.st_mode)) puts("каталог");
    else if (S_ISLNK(st.st_mode)) puts("символическая ссылка");
    else if (S_ISCHR(st.st_mode)) puts("символьное устройство");
    else if (S_ISBLK(st.st_mode)) puts("блочное устройство");
    else if (S_ISFIFO(st.st_mode)) puts("канал FIFO");
    else if (S_ISSOCK(st.st_mode)) puts("сокет");
}
```

`stat` следует за символической ссылкой, а `lstat` описывает саму ссылку.

## Владельцы файлов

- **Владелец (st_uid)** — обычно пользователь, создавший файл (EUID процесса).
- **Группа (st_gid)** — EGID процесса-создателя или группа каталога (если на каталоге стоит SGID или так принято в BSD).
- Менять владельца может только **root**. Группу владелец может сменить на любую группу, в которой состоит сам.

```bash
chown ivan:staff report.txt   # владелец и группа
chgrp staff report.txt
```
```c
chown("report.txt", 1001, 50);     // UID, GID; -1 — не менять
fchown(fd, -1, 50);
```

## Права доступа

<pre class="diagram">
-rwxr-x--x  1 ivan staff 8216 prog
 │││││││││
 ││││││└┴┴─ остальные: --x
 │││└┴┴──── группа:    r-x
 └┴┴─────── владелец:  rwx
</pre>

| Право | Обычный файл | Каталог |
|---|---|---|
| **r** (4) | Читать содержимое | Читать список имён (`ls`) |
| **w** (2) | Изменять содержимое | Создавать, удалять, переименовывать файлы в каталоге |
| **x** (1) | Запускать как программу | «Проходить» через каталог: `cd`, доступ к файлам по имени |

<div class="warn" markdown="1">
Удаление файла зависит от прав на **каталог** (w + x), а не на сам файл. Файл «только для чтения» можно удалить, если есть право записи в каталог (если не установлен sticky bit).
</div>

**Восьмеричная запись:** каждая тройка — одна цифра.

| Права | Число |
|---|---|
| `rwxr-xr-x` | 755 |
| `rw-r--r--` | 644 |
| `rwx------` | 700 |
| `rw-rw----` | 660 |
| `rwxr-x--x` | 751 |

```bash
chmod 640 data.txt
chmod u+x,g-w,o= script.sh     # символьная форма
chmod -R g+rX project/         # рекурсивно, X — только каталогам и исполняемым
```
```c
chmod("data.txt", S_IRUSR | S_IWUSR | S_IRGRP);  // 0640
fchmod(fd, 0600);
```

### Дополнительные биты

| Бит | Число | На файле | На каталоге | В `ls -l` |
|---|---|---|---|---|
| **SUID** | 4000 | Программа выполняется с **EUID владельца** файла (`/usr/bin/passwd` — root) | — | `rws` |
| **SGID** | 2000 | Выполняется с **EGID группы** файла | Новые файлы наследуют **группу каталога** | `r-s` в группе |
| **Sticky** | 1000 | (устарело) | Удалять файлы может только **владелец файла**, каталога или root (`/tmp`) | `t` в остальных |

```bash
chmod 4755 prog     # -rwsr-xr-x
chmod 1777 /tmp     # drwxrwxrwt
```

### umask

**umask** — маска битов, которые **снимаются** с прав новых файлов: права = запрошенные & ~umask.
- `umask 022` → файлы 666 & ~022 = **644**, каталоги 777 & ~022 = **755**.
- `umask 077` → только владелец: 600 и 700.
- Вызов `umask(022)` возвращает старое значение.

### Алгоритм проверки прав ядром

1. Если **EUID = 0** (root) → доступ разрешён (для x нужен хотя бы один бит x).
2. Если **EUID = владелец** файла → проверяются права **владельца**.
3. Иначе, если **EGID** или одна из дополнительных групп = группа файла → права **группы**.
4. Иначе → права **остальных**.

Проверяется **только одна** категория. Если владелец имеет `---`, а остальные `rwx`, владелец доступа не получит.

**Проверка в программе:** `access(path, R_OK | W_OK)` — по **реальным** UID и GID (полезно в SUID-программах).

### Расширенные механизмы

- **POSIX ACL** — права для отдельных пользователей и групп: `setfacl -m u:petr:rw file`, `getfacl`.
- **Атрибуты ext**: `chattr +i` (неизменяемый файл), `lsattr`.
- **Мандатный контроль**: SELinux, AppArmor.
