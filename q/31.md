<div class="tldr" markdown="1">
**Создание процесса:** **`CreateProcess`** создаёт процесс и его главный поток, загружает EXE, возвращает в `PROCESS_INFORMATION` дескрипторы и идентификаторы процесса и потока.

**Создание потока:** **`CreateThread`** (или **`_beginthreadex`** для программ с библиотекой C) создаёт поток в текущем процессе, принимает стартовую функцию и параметр.

**Завершение:** поток — `return` из стартовой функции, `ExitThread`, `TerminateThread` (небезопасно); процесс — `ExitProcess`, `TerminateProcess`, завершение последнего потока. Код возврата — `GetExitCodeProcess`/`GetExitCodeThread`. Ожидание — `WaitForSingleObject(hProcess/hThread, INFINITE)`.

**Синхронизация потоков:**
- **в одном процессе, быстро:** `CRITICAL_SECTION`, `SRWLOCK`, condition variables, `Interlocked*`-функции;
- **объекты ядра** (в том числе между процессами, по имени): **мьютекс**, **семафор**, **событие**, **ожидающий таймер**, а также процесс и поток (становятся сигнальными при завершении);
- ожидание — **`WaitForSingleObject`**, **`WaitForMultipleObjects`**.

Ошибки синхронизации: **гонки**, **тупики** (захват блокировок в разном порядке), утечки незакрытых дескрипторов.
</div>

## Создание процесса

```c
STARTUPINFOW si = { sizeof si };
PROCESS_INFORMATION pi = { 0 };
WCHAR cmd[] = L"notepad.exe file.txt";   // изменяемый буфер!

if (CreateProcessW(NULL, cmd, NULL, NULL, FALSE,
                   CREATE_NEW_CONSOLE, NULL, NULL, &si, &pi)) {
    WaitForSingleObject(pi.hProcess, INFINITE);     // дождаться завершения
    DWORD code; GetExitCodeProcess(pi.hProcess, &code);
    CloseHandle(pi.hThread);                        // закрыть дескрипторы
    CloseHandle(pi.hProcess);
}
```

Параметры `CreateProcess`: имя приложения, командная строка, атрибуты безопасности процесса и потока, **наследование дескрипторов**, **флаги создания** (`CREATE_SUSPENDED` — создать приостановленным, `CREATE_NEW_CONSOLE`, `DETACHED_PROCESS`, класс приоритета), **окружение**, текущий каталог, `STARTUPINFO` (окно, стандартные дескрипторы).

**Отличие от UNIX:** в Windows нет аналога `fork`. `CreateProcess` сразу загружает **новую программу** (как `fork` + `exec` вместе). Дочерний процесс **не является копией** родителя.

Другие функции: `ShellExecute`/`ShellExecuteEx` (открыть файл или URL ассоциированной программой), `WinExec` (устаревшая), `system()` из библиотеки C.

## Создание потока

```c
DWORD WINAPI ThreadFunc(LPVOID param) {
    int id = (int)(intptr_t)param;
    printf("поток %d, TID=%lu\n", id, GetCurrentThreadId());
    return id * 10;                 // код завершения потока
}

HANDLE h = CreateThread(
    NULL,          // атрибуты безопасности
    0,             // размер стека (0 — по умолчанию, 1 МБ)
    ThreadFunc,    // стартовая функция
    (LPVOID)(intptr_t)1,   // параметр
    0,             // флаги (CREATE_SUSPENDED)
    NULL);         // сюда можно получить TID
WaitForSingleObject(h, INFINITE);
DWORD code; GetExitCodeThread(h, &code);
CloseHandle(h);
```

<div class="warn" markdown="1">
Если поток использует функции **библиотеки C** (`printf`, `malloc`, `strtok`), создавайте его через **`_beginthreadex`**, а не `CreateThread`: `_beginthreadex` инициализирует структуры CRT для потока и предотвращает утечки. Завершать такой поток — `_endthreadex`.
</div>

## Завершение

| Способ | Что завершает | Примечание |
|---|---|---|
| `return` из стартовой функции | Текущий поток | **Рекомендуемый** способ: корректно освобождает ресурсы |
| `ExitThread(code)` | Текущий поток | Не вызывает деструкторы C++, для CRT — `_endthreadex` |
| `TerminateThread(h, code)` | Любой поток | **Опасно:** не освобождает стек и блокировки |
| `ExitProcess(code)` | Весь процесс со всеми потоками | Вызывает `DllMain(DLL_PROCESS_DETACH)` |
| `TerminateProcess(h, code)` | Любой процесс | Жёстко, без уведомления DLL |
| Завершение **последнего** потока | Процесс | — |
| Возврат из `main`/`WinMain` | Процесс (неявный `ExitProcess`) | — |

- **Код возврата:** `GetExitCodeThread`, `GetExitCodeProcess`. Пока объект не завершился, возвращается `STILL_ACTIVE`.
- Завершённые процесс и поток становятся **сигнальными**, поэтому их можно дождаться через `WaitForSingleObject`.
- Дескрипторы `hProcess` и `hThread` нужно **закрывать** (`CloseHandle`), иначе объект останется в памяти. Закрытие дескриптора ≠ завершение объекта.

## Синхронизация потоков

### Средства одного процесса (быстрые)

```c
// Критическая секция
CRITICAL_SECTION cs;
InitializeCriticalSection(&cs);
EnterCriticalSection(&cs);  /* КС */  LeaveCriticalSection(&cs);
DeleteCriticalSection(&cs);

// Атомарные операции без блокировок
LONG counter = 0;
InterlockedIncrement(&counter);
InterlockedCompareExchange(&value, newVal, expected);
```

- **`CRITICAL_SECTION`** — быстрое взаимное исключение внутри процесса: без перехода в ядро, если секция свободна. `TryEnterCriticalSection` — без ожидания.
- **`SRWLOCK`** — блокировка чтения-записи (многие читатели или один писатель), очень лёгкая.
- **Interlocked-функции** — атомарные операции над переменной без блокировки.
- **Condition variables** (`SleepConditionVariableCS`, `WakeConditionVariable`) — ожидание условия.

### Объекты синхронизации ядра

Находятся в состоянии **сигнальном (signaled)** или **несигнальном**. Ожидание:
```c
DWORD r = WaitForSingleObject(hObj, 5000);   // до 5 секунд
// WAIT_OBJECT_0 — объект сигнальный; WAIT_TIMEOUT; WAIT_FAILED
WaitForMultipleObjects(n, handles, TRUE, INFINITE);   // TRUE — ждать все
```

| Объект | Создание | Сигнальное состояние | Применение |
|---|---|---|---|
| **Мьютекс** | `CreateMutex` | Свободен (никто не владеет) | Взаимное исключение, **в том числе между процессами** (именованный). Имеет владельца, рекурсивный |
| **Семафор** | `CreateSemaphore` | Счётчик > 0 | Ограничение числа потоков, пул ресурсов |
| **Событие** | `CreateEvent` | «Установлено» (`SetEvent`) | Оповещение. **С автосбросом** (будит один поток) или **ручным сбросом** (будит все, `ResetEvent`) |
| **Ожидающий таймер** | `CreateWaitableTimer` | Истёк | Задержки, периодические задачи |
| **Процесс, поток** | — | Завершился | Ожидание завершения |

```c
HANDLE hMutex = CreateMutexW(NULL, FALSE, L"Global\\MyAppMutex");  // имя — для разных процессов
WaitForSingleObject(hMutex, INFINITE);   // захватить
/* работа с общим ресурсом */
ReleaseMutex(hMutex);
// проверка «одна копия программы»:
if (GetLastError() == ERROR_ALREADY_EXISTS) { /* уже запущена */ }
```

**Сравнение:**

| | `CRITICAL_SECTION` | Мьютекс (объект ядра) |
|---|---|---|
| Область | Один процесс | Между процессами (именованный) |
| Скорость | Высокая (без ядра при отсутствии конфликта) | Ниже (переход в ядро) |
| Ожидание нескольких объектов | Нет | Да (`WaitForMultipleObjects`) |
| Тайм-аут | Нет (только `TryEnter`) | Да |

### Задача «производители–потребители» и тупики

Решается семафорами `empty`, `full` и мьютексом ([вопрос 5]({{ '/q/05.html' | relative_url }})).

**Тупик** в Windows возникает, если потоки захватывают **несколько объектов в разном порядке**:
```c
// Поток 1              // Поток 2
WaitForSingleObject(A)  WaitForSingleObject(B)
WaitForSingleObject(B)  WaitForSingleObject(A)   // ⟳ взаимная блокировка
```
Решение — **единый порядок** захвата, `WaitForMultipleObjects(..., bWaitAll = TRUE)` (атомарный захват нескольких объектов), тайм-ауты. Подробно: [вопрос 6]({{ '/q/06.html' | relative_url }}).

## Пример: подсчёт в нескольких потоках

```c
#define N 4
volatile LONG total = 0;
CRITICAL_SECTION cs;

DWORD WINAPI Worker(LPVOID p) {
    for (int i = 0; i < 1000000; i++) {
        EnterCriticalSection(&cs);
        total++;                    // защищённый общий счётчик
        LeaveCriticalSection(&cs);
    }
    return 0;
}

int main(void) {
    InitializeCriticalSection(&cs);
    HANDLE t[N];
    for (int i = 0; i < N; i++)
        t[i] = CreateThread(NULL, 0, Worker, NULL, 0, NULL);
    WaitForMultipleObjects(N, t, TRUE, INFINITE);
    for (int i = 0; i < N; i++) CloseHandle(t[i]);
    DeleteCriticalSection(&cs);
    printf("total = %ld\n", total);   // ровно 4000000
    return 0;
}
```
