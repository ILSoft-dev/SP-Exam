<div class="tldr" markdown="1">
**Виртуальное адресное пространство (ВАП)** процесса — диапазон виртуальных адресов, которые процесс может использовать. Его размер определяется разрядностью: **4 ГБ** для 32 бит, **128 ТБ** пользовательской части для x86-64 в Windows и Linux.

ВАП **структурировано** — делится на области с разным назначением и правами:
- **пользовательская часть** — своя у каждого процесса: код программы (`.text`), данные (`.data`, `.bss`), **куча**, **стеки потоков**, загруженные **DLL / .so**, **проецируемые файлы**, окружение;
- **системная часть (ядро)** — **общая** для всех процессов, доступна только в режиме ядра: код ядра и драйверов, пулы памяти, кеш, таблицы страниц.

**Windows x86 (32 бита):** 0–2 ГБ — процесс (до 3 ГБ с ключом `/3GB`), 2–4 ГБ — система. Внизу недоступная область **NULL** (64 КБ). **Linux x86 (32 бита):** 0–3 ГБ — пользователь, 3–4 ГБ — ядро.

В Windows память процесса состоит из **регионов**, которые сначала **резервируются**, затем **передаются (commit)** физической памятью или файлом подкачки (`VirtualAlloc`).
</div>

## Зачем структурировать адресное пространство

- **Защита:** ядро недоступно из пользовательского режима, код нельзя изменять, стек и данные нельзя выполнять (DEP/NX).
- **Изоляция процессов:** у каждого своя пользовательская часть.
- **Эффективность:** системная часть одинакова во всех процессах, поэтому при системном вызове не нужно переключать адресное пространство.
- **Удобство:** стек и куча растут навстречу друг другу, библиотеки загружаются в отдельные области.
- **Ловушки ошибок:** неотображённые области (например, вокруг адреса 0) ловят обращения по нулевым и неверным указателям.

## Windows

### 32-битная Windows (x86)

| Диапазон | Назначение |
|---|---|
| 0x00000000–0x0000FFFF | **Область NULL-указателей** (64 КБ), недоступна |
| 0x00010000–0x7FFEFFFF | **Пользовательский режим**: EXE, DLL, куча, стеки, проецируемые файлы |
| 0x7FFF0000–0x7FFFFFFF | Недоступная область 64 КБ на границе |
| 0x80000000–0xFFFFFFFF | **Режим ядра**: ядро, HAL, драйверы, пулы, кеш, таблицы страниц |

- Ключ загрузки **`/3GB`** (`bcdedit /set increaseuserva 3072`) отдаёт процессу до 3 ГБ, если программа собрана с флагом `/LARGEADDRESSAWARE`.
- 32-битный процесс в 64-битной Windows (WOW64) может получить **4 ГБ**.

### 64-битная Windows (x64)

- Пользовательская часть: **0 – 0x00007FFF`FFFFFFFF** (128 ТБ, начиная с Windows 8.1).
- Системная часть: верхние 128 ТБ (каноническая форма адресов x86-64, 48 бит).
- Между ними — «дыра» неканонических адресов.

### Регионы, резервирование и передача памяти

Память в Windows выделяется в два этапа:
1. **Резервирование (reserve)** — выделяется диапазон адресов (**регион**), выровненный на **64 КБ** (гранулярность выделения), размером, кратным странице. Физическая память не тратится.
2. **Передача (commit)** — региону сопоставляется физическая память или место в **файле подкачки**. Страница получает **атрибуты защиты**: `PAGE_READONLY`, `PAGE_READWRITE`, `PAGE_EXECUTE_READ`, `PAGE_NOACCESS`, `PAGE_GUARD`.

```c
// зарезервировать 1 МБ, передать первые 64 КБ
BYTE *p = VirtualAlloc(NULL, 1 << 20, MEM_RESERVE, PAGE_NOACCESS);
VirtualAlloc(p, 64 * 1024, MEM_COMMIT, PAGE_READWRITE);
p[0] = 42;
VirtualProtect(p, 4096, PAGE_READONLY, &old);  // сменить защиту
VirtualFree(p, 0, MEM_RELEASE);               // освободить регион
```

**Состояния страниц:** свободная (free), зарезервированная (reserved), переданная (committed). Узнать информацию о регионе можно функцией `VirtualQuery`.

**Механизмы управления памятью в Win32:**
- **виртуальная память** — `VirtualAlloc`, для больших массивов;
- **проецируемые в память файлы** — `CreateFileMapping` + `MapViewOfFile`: файлы, загрузка EXE и DLL, разделяемая память;
- **кучи** — `HeapCreate`, `HeapAlloc`, `GetProcessHeap`, а также `malloc` и `new`: множество мелких объектов.

**Стек потока:** резервируется (по умолчанию 1 МБ), передаётся постепенно. Ниже переданной части стоит **сторожевая страница (PAGE_GUARD)**. При обращении к ней стек расширяется, а при исчерпании возникает **переполнение стека** (stack overflow).

## Linux

- 32 бита: **0–3 ГБ** — пользователь, **3–4 ГБ** — ядро (разбиение 3G/1G).
- 64 бита: **0 – 0x00007FFF`FFFFFFFF** — пользователь (128 ТБ), верхняя половина — ядро.
- Области процесса (VMA, `vm_area_struct`): **text, data, bss, heap** (растёт через `brk`/`sbrk`), **mmap-область** (библиотеки, `mmap`, большие `malloc`), **стек**, `vdso`.
- Карту памяти процесса показывают `cat /proc/<pid>/maps` и `pmap <pid>`.

```text
00400000-00452000 r-xp  /usr/bin/prog        ← код
00651000-00652000 rw-p  /usr/bin/prog        ← данные
0145c000-0147d000 rw-p  [heap]
7f2a1c000000-...  r-xp  /lib/x86_64-linux-gnu/libc.so.6
7ffd4a6e1000-...  rw-p  [stack]
```

## Безопасность: ASLR и DEP

- **ASLR** (рандомизация размещения адресного пространства) — базовые адреса EXE, DLL, кучи и стека выбираются **случайно** при каждом запуске. Это затрудняет эксплуатацию уязвимостей.
- **DEP / NX** — страницы данных и стека помечаются как **невыполняемые**.
