<div class="tldr" markdown="1">
**Отладка режима ядра** нужна для поиска ошибок в **драйверах, ядре и системных компонентах** — там, где обычный отладчик приложений бессилен.

**Инструменты** (пакет **Debugging Tools for Windows** из Windows SDK/WDK):
- **WinDbg** — графический и современный отладчик (WinDbg Preview / WinDbg);
- **KD** — консольный отладчик ядра;
- **CDB / NTSD** — консольные отладчики пользовательского режима;
- **GFlags**, **Driver Verifier** — вспомогательные средства.

**Режимы (способы) отладки ядра:**
- **локальная** отладка ядра работающей системы (ограниченная);
- **удалённая «вживую»** — целевая и управляющая машины соединены по **сети (KDNET)**, **COM** (нуль-модем), **USB**, **IEEE 1394 (FireWire)**;
- через **виртуальную машину** (именованный канал COM);
- анализ **аварийного дампа** (`.dmp`) после «синего экрана» (BSOD) — посмертно.

**Компоненты отладчика:** **движок отладки** (`dbgeng.dll`), **расширения** (`.dll`, команды `!…`), **провайдеры символов** (`dbghelp.dll`, **PDB**-файлы, сервер символов), интерфейс пользователя, транспорт связи с целью. На целевой системе работает **встроенный в ядро механизм отладки**.
</div>

## Отладка пользовательского режима и режима ядра

| | Пользовательский режим | Режим ядра |
|---|---|---|
| Что отлаживаем | Приложения (EXE, DLL) | Ядро, драйверы, системные структуры |
| Отладчик | WinDbg, Visual Studio, CDB, x64dbg | WinDbg, KD |
| Где выполняется отладчик | На той же машине | Обычно на **второй** машине (хост) |
| При остановке | Останавливается один процесс | Останавливается **вся целевая система** |
| Доступ | Память процесса | Вся физическая и виртуальная память, регистры, структуры ядра |

При отладке ядра целевая система **полностью замирает** на точке останова, поэтому обычно нужны **две машины** (host — debugger, target — debuggee) или виртуальная машина.

## Режимы (способы) отладки ядра

| Способ | Описание |
|---|---|
| **Локальная отладка ядра** | Отладчик работает **на той же** работающей системе. Можно смотреть структуры ядра, но нельзя ставить точки останова и смотреть регистры (система не замораживается). `kd -kl`, нужен тестовый режим |
| **Удалённая «живая» отладка** | Две машины. Соединение: **сеть (KDNET)** — самый быстрый и современный способ; **COM** (нуль-модемный кабель, медленно); **USB 2.0/3.0**; **IEEE 1394**. На цели включается отладка через `bcdedit /debug on` и настройку транспорта |
| **Через виртуальную машину** | Цель — ВМ (Hyper-V, VMware). Связь через **именованный канал**, эмулирующий COM, либо KDNET. Удобно и безопасно для учёбы |
| **Анализ аварийного дампа** | После BSOD система записывает **дамп памяти** (`MEMORY.DMP`, минидамп). Отладчик открывает его **посмертно**: `!analyze -v` находит причину |

Виды дампов: **полный** (вся физическая память), **памяти ядра** (только режим ядра), **минидамп** (маленький, основное состояние), **активной памяти**.

Включение отладки на цели:
```text
bcdedit /debug on
bcdedit /dbgsettings net hostip:w.x.y.z port:50000 key:...   (KDNET)
bcdedit /dbgsettings serial debugport:1 baudrate:115200      (COM)
```

## Компоненты отладчика

<pre class="diagram">
 Управляющая машина (host)          Целевая (target)
┌──────────────────────────┐       ┌──────────────────┐
│ Интерфейс (WinDbg GUI/CLI)│       │ Отлаживаемое ядро│
│        │                  │       │ + драйверы       │
│ Движок dbgeng.dll         │◄─────►│ Встроенный в ядро│
│   ├ работа с символами    │ сеть/ │ механизм отладки │
│   │  dbghelp.dll + PDB    │ COM/  │ (KD stub)        │
│   ├ расширения !команды   │ USB   │                  │
│   └ транспорт (KDNET...)  │       │                  │
└──────────────────────────┘       └──────────────────┘
</pre>

| Компонент | Назначение |
|---|---|
| **Интерфейс пользователя** | WinDbg (окна дизассемблера, памяти, стека, регистров, watch) или командная строка KD |
| **Движок отладки** (`dbgeng.dll`) | Ядро отладчика: выполнение команд, точки останова, чтение памяти и регистров, пошаговое выполнение. Общий для всех отладчиков |
| **Провайдер символов** (`dbghelp.dll`) | Сопоставляет адреса с **именами функций и переменных** по **PDB**-файлам. Загружает символы с **сервера символов** Microsoft |
| **Расширения** (`.dll`: `kdexts`, `ext`, `uext`) | Команды вида `!process`, `!thread`, `!analyze`, `!pool`, `!irp` для разбора структур ядра |
| **Транспорт** | Протокол и канал связи с целевой системой (KDNET, COM, USB, именованный канал) или чтение файла дампа |
| **Механизм отладки в ядре цели** | Встроен в `ntoskrnl`; обрабатывает запросы хоста, точки останова, пересылает состояние |

### Символы (symbols) и PDB

- **PDB (Program Database)** — файлы с отладочной информацией: имена функций, переменных, типов, номера строк.
- Без символов отладчик видит только адреса. С символами — осмысленные имена и стек вызовов.
- **Сервер символов** Microsoft: `srv*c:\symbols*https://msdl.microsoft.com/download/symbols`, переменная `_NT_SYMBOL_PATH`.

## Работа в отладчике

**Точки останова:** программные (замена команды на `int 3`), аппаратные (регистры отладки DR0–DR3, в том числе на **доступ к данным** — `ba`), условные.

**Типичные команды WinDbg / KD:**

| Команда | Действие |
|---|---|
| `g` | Продолжить выполнение (go) |
| `p` / `t` | Шаг с обходом / с заходом (step over / trace into) |
| `bp nt!ZwCreateFile` | Точка останова на функции |
| `ba w4 addr` | Останов на запись 4 байт по адресу |
| `k` | Стек вызовов |
| `r` | Регистры |
| `dd / dq / db addr` | Дамп памяти |
| `u addr` | Дизассемблировать |
| `!process 0 0` | Список процессов |
| `!thread` | Текущий поток |
| `!analyze -v` | Анализ аварии (BSOD) |
| `lm` | Загруженные модули |
| `.reload` | Перезагрузить символы |

**Driver Verifier** (`verifier.exe`) — не отладчик, а средство, которое нагружает драйвер проверками (неверная работа с памятью, IRQL, пулами) и вызывает BSOD с точным диагнозом в точке ошибки.
