<div class="tldr" markdown="1">
**Windows NT** (Windows 2000 … 11) — ОС с **гибридным ядром**.

**Режим ядра:**
- **HAL** — уровень абстрагирования оборудования;
- **ядро (kernel)** — планирование потоков, прерывания, синхронизация;
- **исполнительная система (executive)**, `ntoskrnl.exe`: диспетчеры объектов, процессов и потоков, памяти, ввода-вывода, кеша, PnP, электропитания, монитор безопасности, диспетчер конфигурации (реестр), механизм ALPC;
- **драйверы устройств**;
- **win32k.sys** — оконная и графическая подсистема.

**Пользовательский режим:**
- **системные процессы**: smss, csrss, wininit, winlogon, lsass, services;
- **службы**;
- **подсистемы окружения**;
- **приложения**, которые вызывают **DLL подсистемы** (kernel32, user32, gdi32, advapi32). Эти DLL обращаются к **NTDLL.DLL**, а она — к ядру.

**Реестр** — иерархическая база данных конфигурации ОС и программ. Корневые разделы:
- **HKEY_LOCAL_MACHINE** (HKLM);
- **HKEY_CURRENT_USER** (HKCU);
- **HKEY_CLASSES_ROOT** (HKCR);
- **HKEY_USERS** (HKU);
- **HKEY_CURRENT_CONFIG** (HKCC).

Реестр хранится в файлах-**кустах** (hives). Типы значений: REG_SZ, REG_DWORD, REG_QWORD, REG_BINARY, REG_MULTI_SZ, REG_EXPAND_SZ. Инструменты: `regedit`, `reg.exe`, функции `RegOpenKeyEx`, `RegQueryValueEx`, `RegSetValueEx`, `RegCloseKey`.
</div>

## Компоненты режима ядра

| Компонент | Назначение |
|---|---|
| **HAL** (`hal.dll`) | Скрывает различия аппаратных платформ: контроллеры прерываний, таймеры, многопроцессорность |
| **Ядро** (нижняя часть `ntoskrnl.exe`) | Диспетчеризация и планирование потоков, обработка прерываний и исключений, синхронизация в многопроцессорной системе. Объекты ядра: события, мьютексы, DPC, APC |
| **Исполнительная система** (верхняя часть `ntoskrnl.exe`) | Набор диспетчеров, каждый отвечает за свой ресурс (см. ниже) |
| **Драйверы** (`.sys`) | Устройства, файловые системы, сетевые протоколы, фильтры ([вопрос 38]({{ '/q/38.html' | relative_url }})) |
| **win32k.sys** | Оконный менеджер (USER) и графика (GDI) в режиме ядра ([вопрос 28]({{ '/q/28.html' | relative_url }})) |

**Диспетчеры исполнительной системы:**
- **диспетчер объектов** — создание, именование, защита и учёт объектов (процессы, файлы, события);
- **диспетчер процессов и потоков**;
- **диспетчер памяти** — виртуальная память, подкачка;
- **диспетчер ввода-вывода** — пакеты IRP, стек драйверов;
- **диспетчер кеша**;
- **диспетчер PnP** и **диспетчер электропитания**;
- **монитор безопасности (SRM)** — проверка прав доступа;
- **диспетчер конфигурации** — реализует реестр;
- **ALPC** — быстрый обмен сообщениями между процессами.

## Компоненты пользовательского режима

| Процесс | Назначение |
|---|---|
| **System** (PID 4) | Потоки ядра |
| **smss.exe** | Диспетчер сеансов: первый процесс пользовательского режима |
| **csrss.exe** | Процесс подсистемы Windows (консоль, часть работы с процессами) |
| **wininit.exe** | Инициализация сеанса 0, запуск служб и lsass |
| **winlogon.exe** | Вход и выход пользователя, Ctrl+Alt+Del |
| **lsass.exe** | Проверка подлинности, политика безопасности |
| **services.exe** | Диспетчер служб (SCM) |
| **svchost.exe** | Хост-процесс для служб, реализованных в DLL |
| **explorer.exe** | Оболочка пользователя |

**Подсистемы окружения** дают приложениям определённый программный интерфейс. Основная — **подсистема Windows (Win32)**. Исторически были подсистемы POSIX и OS/2. Сейчас Linux-программы запускаются через **WSL**.

**Путь вызова функции:** приложение вызывает `CreateFile` в `kernel32.dll`/`kernelbase.dll` → `NtCreateFile` в **NTDLL.DLL** → переход в режим ядра → системная служба `NtCreateFile` в ntoskrnl → диспетчер ввода-вывода → драйвер ФС. Подробно: [вопрос 39]({{ '/q/39.html' | relative_url }}).

## Системный реестр

**Реестр** — централизованная иерархическая база данных, которая заменила файлы `.ini`. В ней хранятся параметры оборудования, драйверов, служб, ОС, пользователей и программ, а также сопоставления файлов.

### Структура

- **Разделы (ключи)** — как каталоги, могут содержать подразделы.
- **Параметры (значения)** — тройки «имя, тип, данные».

| Корневой раздел | Содержимое |
|---|---|
| **HKEY_LOCAL_MACHINE** (HKLM) | Настройки компьютера: `HARDWARE`, `SAM`, `SECURITY`, `SOFTWARE`, `SYSTEM` (службы, драйверы: `SYSTEM\CurrentControlSet\Services`) |
| **HKEY_CURRENT_USER** (HKCU) | Настройки текущего пользователя: рабочий стол, `Software\…` программ. Ссылка на его раздел в HKU |
| **HKEY_USERS** (HKU) | Профили всех загруженных пользователей (по SID) и `.DEFAULT` |
| **HKEY_CLASSES_ROOT** (HKCR) | Сопоставления расширений файлов и регистрация COM-классов. Объединение `HKLM\Software\Classes` и `HKCU\Software\Classes` |
| **HKEY_CURRENT_CONFIG** (HKCC) | Текущий профиль оборудования. Ссылка в HKLM |

### Типы значений

| Тип | Содержимое |
|---|---|
| `REG_SZ` | Строка |
| `REG_EXPAND_SZ` | Строка с переменными окружения (`%SystemRoot%`) |
| `REG_MULTI_SZ` | Список строк |
| `REG_DWORD` | 32-битное число |
| `REG_QWORD` | 64-битное число |
| `REG_BINARY` | Двоичные данные |

### Хранение

- Реестр хранится в файлах-**кустах (hives)**: `%SystemRoot%\System32\config\` (`SYSTEM`, `SOFTWARE`, `SAM`, `SECURITY`, `DEFAULT`) и `NTUSER.DAT` в профиле пользователя.
- Ветвь `HKLM\HARDWARE` создаётся при загрузке и на диске не хранится.
- Изменения журналируются (файлы `.LOG`), поэтому реестр устойчив к сбоям.
- Доступ к разделам защищён списками ACL.

### Использование в программах

```c
#include <windows.h>

HKEY h;
DWORD val = 42, type, size = sizeof(DWORD), data;

// создать или открыть раздел своего приложения
RegCreateKeyExW(HKEY_CURRENT_USER, L"Software\\MyCompany\\MyApp",
                0, NULL, 0, KEY_READ | KEY_WRITE, NULL, &h, NULL);
RegSetValueExW(h, L"Counter", 0, REG_DWORD, (BYTE *)&val, sizeof val);
RegQueryValueExW(h, L"Counter", NULL, &type, (BYTE *)&data, &size);
RegCloseKey(h);
```

Другие функции: `RegOpenKeyEx`, `RegEnumKeyEx`, `RegEnumValue`, `RegDeleteValue`, `RegDeleteKey`, `RegGetValue`, `RegNotifyChangeKeyValue` (уведомление об изменениях).

В .NET используется класс `Microsoft.Win32.Registry`.

### Инструменты

- **regedit** — графический редактор, экспорт и импорт `.reg`-файлов.
- **reg.exe**:
  ```text
  reg query  HKCU\Software\MyApp
  reg add    HKCU\Software\MyApp /v Counter /t REG_DWORD /d 5
  reg delete HKCU\Software\MyApp /v Counter
  reg export HKCU\Software\MyApp backup.reg
  ```
- PowerShell: `Get-ItemProperty HKCU:\Software\MyApp`.

<div class="warn" markdown="1">
Перед ручным изменением реестра сделайте экспорт раздела или точку восстановления. Ошибка в `HKLM\SYSTEM` может помешать загрузке системы.
</div>
